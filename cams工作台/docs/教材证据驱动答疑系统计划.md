# 教材证据驱动答疑系统计划

## 1. 当前目标

构建一个**答疑驱动的学生理解诊断系统**。

学生刷题时在题目下提问，系统给出有教材依据的回答；同时，每一次提问都被记录和分类，沉淀成教研可用的诊断数据：哪些题被反复问、哪些选项最容易误导、哪些知识点学生普遍没懂、哪些解析需要重写。

但现阶段不能直接做学生答疑。当前最先要验证的是底层能力：

> 给系统一道题，系统能不能在不看现有解析的情况下，从教材中找到这道题真正需要的证据。

如果“题目 → 教材证据”的检索能力不成立，后面的推理桥梁、答疑生成、诊断统计都会变成手工样例，不是系统能力。

## 2. 系统类型边界

现在必须区分两个系统。

### 2.1 解答生成系统（当前阶段）

用于验证“教材证据检索与解析生成”能力。

| 维度 | 说明 |
|---|---|
| 是否看现有解析 | 不看。现有解析可能本身有误，不能作为输入 |
| 输入 | 题干、全部选项、正确答案、教材原文 |
| 目的 | 验证系统能否独立从教材中找到证据并推导解释 |
| 输出 | 候选教材证据、证据与选项关系、推理桥梁、可追溯解析 |
| 评估 | 生成后再与教研解析/真实答疑对照 |

### 2.2 学生答疑系统（后续阶段）

用于回答学生在题目下的具体问题。

| 维度 | 说明 |
|---|---|
| 是否看现有解析 | 可以，但只能作为上下文，不是证据 |
| 输入 | 题干、选项、正确答案、现有解析、学生问题、教材原文 |
| 目的 | 针对学生具体困惑解释为什么对/错 |
| 输出 | 带教材引用的回答、问题类型标注、误解点标注 |
| 评估 | 对比教研真实答疑，检查学生是否还需要追问 |

当前阶段先做 **2.1 解答生成系统的证据检索能力**。学生答疑系统等证据检索与归因跑通后再做。

## 3. 核心链路

最终完整链路如下：

```text
题目上下文 / 学生问题
  → 字面种子检索 + 教材概念候选召回
  → LLM 基于候选概念分析题目并生成检索计划
  → 多路召回教材候选证据
  → 逐条标注证据与选项的关系
  → 写出教材到选项判断的推理桥梁
  → 生成带编号引用的解析/答疑
  → 引用审计 + 推理审计
  → 教研审核/修改
  → 沉淀诊断数据
```

其中最关键的不是“LLM 生成回答”，而是中间两步：

- **证据归因**：这段教材到底支持正确答案、反证干扰项、解释学生误解，还是无关。
- **推理桥梁**：教材原文和选项判断之间不是自动等号，必须写清楚“这段教材如何推到这个选项对/错”。

## 4. 现有图与卡片的定位

现有知识图谱和卡片不是废掉，但它们只能作为**教材内容索引**，不能直接当“题目证据索引”。

以 `2.1_19 D 公司税增加` 为例：

- 图里存在 `税收损失`、`贸易洗钱`、`空壳公司`、`税务欺诈`、`黑市比索交易` 等概念。
- 但从 `税收损失` 出发，当前图谱没有通往 `贸易洗钱 / 空壳公司 / 税务欺诈 / 黑市比索交易` 的教研推理路径。
- 原因是基础图记录的是教材显性关系，不记录“这条教材证据在某道题里可用于反证某个选项”。

因此后续要拆成三层：

```text
基础教材图：教材讲了什么
LLM 检索计划：这道题可能要找什么
题目证据归因层：这条教材证据在这道题里有什么用
```

不要把所有东西都塞进基础知识图谱。例如不要粗暴新增：

```text
税收损失 → 贸易洗钱
```

更合理的是新增题目归因记录：

```text
OptionClaim: 2.1_19_D「公司税增加」

contradicted_by:
- 洗钱导致政府税收缩水
- 黑市比索交易规避国内税收和关税

explained_by:
- 贸易洗钱通过贸易转移价值
- 空壳公司/虚假发票/税务欺诈用于伪造交易背景

reasoning_bridge:
- D 的主体是 FI 公司税
- 教材证据指向政府税收缩水、逃税、规避税收和关税
- 主体不一致，方向也不一致，所以 D 不选
```

## 5. 证据来源原则

证据必须分级。

| 类型 | 可否作为最终证据 | 说明 |
|---|---|---|
| 教材原文 | 可以 | 一手证据，最终回答必须回到这里 |
| 题干/选项/正确答案 | 不是证据，是题目上下文 | 用来确定要证明什么、反证什么 |
| 学生原问题 | 不是证据，是困惑定位 | 用来判断学生卡在哪里 |
| 现有解析 | 解答生成阶段不能看；学生答疑阶段只能作上下文 | 解析可能有误，不能作为独立证据 |
| 卡片/知识图谱 | 可作为候选证据单元/索引 | 如果卡片含有教材原文引文、上下文和稳定来源，可直接作为 evidence chunk；若引文太短或上下文不足，必须回到教材原文补齐 |

系统不追求强行回答所有题。遇到教材证据不足、题目本身有歧义、正确答案依赖外部背景时，应标记“证据不足，转教研”。

## 6. 第零阶段：真实答疑分析

目的：理解学生真实在问什么，避免做成只有教研能用的内容浏览器。

已完成：

- 读 37 条真实答疑。
- 初步产出 `学生答疑问题分析.md`。
- 发现高频问题不是“要答案”，而是“为什么这个选项对/错”“教材依据在哪里”“我这个理解哪里错了”。

当前结论：

- 学生带着自己的错误推理来问，不是白纸。
- 许多问题需要解释干扰项，而不是只解释正确答案。
- 一部分问题需要跨段证据链，不能只做关键词匹配。

第零阶段为后续学生答疑系统提供问题类型和误解类型，但当前阶段先不直接做学生答疑。

## 7. 第一阶段（当前）：题目到教材证据检索器 MVP

### 7.1 目标

搭建一个最小可用的证据检索器：

> 输入一道题，输出可能相关的教材证据候选。

这一阶段不生成学生回答，不做完整解析，不做 UI。

### 7.2 输入边界

允许输入：

- `question_id`
- 题干
- 全部选项
- 正确答案
- 章节范围
- 教材原文

禁止输入：

- 现有解析
- 教研答疑
- 已写好的证据包
- 之前 AI 对该题的分析

这些材料只能在检索完成后用于对照评估。

### 7.3 MVP 输出

每道题输出一个证据候选报告：

```json
{
  "question_id": "2.1_19",
  "retrieval_plan": {
    "stem_anchors": ["洗钱", "金融机构", "后果"],
    "answer_anchors": ["盈利业务减少", "调查费用", "罚金"],
    "distractor_anchors": {
      "D": ["公司税增加", "税收", "税务", "政府税收", "逃税", "关税"]
    },
    "chapter_anchors": ["洗钱的经济和社会影响", "社会成本"]
  },
  "candidate_evidence": [
    {
      "evidence_id": "E1",
      "source": "教材原文/卡片ID/行号",
      "quote": "教材原文",
      "retrieved_by": ["D: 税收", "章节: 社会成本"],
      "possible_relation": "反证D",
      "notes": "待归因确认"
    }
  ]
}
```

### 7.4 检索流程

第一版先做实验台，不追求完整自动化。

```text
1. 审计 2.1 现有卡片是否可直接作为 evidence chunks
   - 卡片是否有稳定 `card_id`
   - `citation` 是否为教材原文，而不是过短关键词
   - `context_before/context_after` 是否足够支撑理解
   - 是否能反查到教材原文位置
   - 如果卡片足够，第一版直接用卡片作为检索语料；如果不足，再回到教材原文补切

2. LLM 做题目拆解
   - 题干在问什么
   - 每个选项声称了什么
   - 正确答案需要哪些证据
   - 错误选项可能需要哪些反证

3. 建立教材概念候选索引
   - 从卡片的 `knowledge/citation/context_before/context_after` 抽出概念词
   - 保留概念出现在哪些 card_id
   - 保留章节、卡片类型、邻近概念
   - 这一步的作用是让 LLM 知道“教材里大概有哪些可用概念”

4. 机械种子检索
   - 先用题干、选项、正确答案中的字面词做关键词/语义检索
   - 不要求这一步找全，只要求拿到第一批候选卡片和候选概念
   - 例如 `公司税/税收/金融机构后果` 先召回 `税收损失/政府税收缩水/FI负面影响` 等种子

5. LLM 基于候选概念生成检索锚点
   - LLM 不能凭空想锚点，必须基于机械检索返回的候选概念和题目选项扩展
   - 输出题干锚点、正确答案锚点、干扰项锚点、上位概念/机制概念/近义概念
   - 如果候选概念不足，标记“需要扩大检索范围”，而不是硬造概念

6. 多路检索
   - 教材原文关键词检索
   - 卡片检索
   - 三元组检索
   - 图谱邻近概念检索
   - 必要时语义检索

7. 合并去重
   - 保留证据来源
   - 记录由哪个锚点召回
   - 不在本阶段强行判断最终对错
```

### 7.5 第一题盲测：2.1_19

先用 `2.1_19` 做盲检索实验。

题目：洗钱会对金融机构 FI 造成哪些后果？  
正确答案：A、E  
重点干扰项：D 公司税的增加

盲测要求：

- 不看现有解析。
- 不看教研答疑。
- 不看已有证据包。
- 只用题干、选项、正确答案和教材。

检索完成后再对照教研材料，检查系统是否召回了这些关键证据类型：

- FI 负面影响列表。
- 税收损失/政府税收缩水。
- 贸易洗钱。
- 空壳公司/虚假发票/税务欺诈。
- 黑市比索交易中规避税收和关税的内容。

### 7.6 成功标准

第一阶段不看回答质量，只看检索质量。

- 关键证据召回率：教研使用的主干证据不能漏。
- 候选数量可控：不能给教研几十条噪声。
- 召回原因可解释：每条证据都知道是由哪个锚点召回的。
- 能识别证据缺口：找不到充分证据时能标记，不强行补。
- 2.1_19 至少能召回 D 选项所需的跨段证据主干。

如果第一阶段跑不通，停止做答疑生成，优先改检索器。

## 8. 第二阶段：证据归因与推理桥梁

第一阶段只返回候选证据。第二阶段要判断证据用途。

每条证据需要标注：

| 字段 | 含义 |
|---|---|
| `evidence_id` | 证据编号 |
| `source_quote` | 教材原文 |
| `evidence_relation` | 支持正确答案 / 反证干扰项 / 解释误解 / 无关 |
| `target_option` | 对应哪个选项 |
| `evidence_strength` | 直接支持 / 可推导 / 辅助解释 / 证据不足 |
| `reasoning_bridge` | 这段教材如何推到选项判断 |
| `confidence` | 高 / 中 / 低 / 需教研复核 |

以 `2.1_19 D` 为例，归因不是“找到税收损失段”就结束，而是要写清楚：

```text
教材说洗钱使政府税收缩水。
D 说的是 FI 公司税增加。
政府税收与 FI 公司税主体不同，方向也不同。
所以该证据反证 D，而不是支持 D。
```

第二阶段产出的是“题目证据归因层”，不是学生回答。

## 9. 第三阶段：解析/答疑生成

证据归因通过后，再让 LLM 生成解析或学生回答。

生成要求：

- 每个关键判断必须带证据编号。
- 不能写“教材指出”这种不可追溯表述。
- 不能使用未进入证据归因表的材料。
- 必须解释正确答案为什么对。
- 必须解释核心干扰项为什么错。
- 当证据不足时，明确说“教材没有直接写到这一点，需要教研复核”。

学生答疑版本还要满足：

- 先直接回应学生问的具体问题。
- 控制字数，避免长篇教材复述。
- 解释学生可能误解在哪里。
- 给出下次判断方法。

## 10. 第四阶段：引用审计与教研审核

引用审计不是只检查引用编号是否存在，还要检查引用是否支撑结论。

审计问题：

- 回答中的每个引用是否存在于证据表？
- 引用段落是否真的包含该内容？
- 引用是否足以支持该判断？
- 有没有“引用存在，但推理跳步”？
- 有没有未引用的关键判断？

教研审核从“重写回答”变成“挑错”：

- 引用对不对。
- 推理有没有跳步。
- 干扰项解释是否准确。
- 学生能不能看懂。
- 是否允许进入学生侧。

## 11. 第五阶段：诊断数据沉淀

学生答疑系统上线后，每次提问和回答都沉淀诊断数据：

```json
{
  "question_id": "2.1_19",
  "student_question": "虚假交易不会交税吗，为什么D不选？",
  "question_type": "为什么不选某个干扰项",
  "target_option": "D",
  "misconception": "把政府税收损失/洗钱者逃税误解为 FI 公司税增加",
  "evidence_coverage": "cross_section_supported",
  "system_confidence": "medium",
  "teacher_review_status": "approved_with_minor_edit"
}
```

教研侧可统计：

- 哪些题被问得最多。
- 哪些选项被追问最多。
- 学生常见误解点。
- 哪些题解析需要重写。
- 哪些内容适合做专题课或易错卡片。

## 12. 上线策略

不直接对学生开放。分三轮：

### 12.1 内部影子模式

- 系统生成证据、推理桥梁和回答。
- 只给内部和教研看。
- 不展示给学生。

### 12.2 教研审核后发布

- 学生提问后，系统生成回答。
- 教研审核通过后才展示。
- 记录教研修改了什么。

### 12.3 分置信度发布

- 高置信：自动回答，教研抽查。
- 中置信：教研审核后发布。
- 低置信/证据不足：直接转教研。

进入下一轮的条件：

- 内部审核通过率达到 80% 以上。
- 教研大改率低于 20%。
- 未出现无证据强答的高风险回答。

## 13. 当前最小下一步

当前不再继续重做手工证据包，也不直接生成学生回答。

下一步是：

1. 先审计 2.1 现有卡片能否作为 evidence chunks。
   - 若卡片引文完整、上下文足够、来源稳定，第一版直接用卡片。
   - 若卡片只有关键词式引文、上下文不足或无法反查原文，再回到教材原文补切。
2. 锁定第一版检索语料：优先使用 `cards_ch2.json` 中的 2.1 卡片，必要时补充教材原文段落。
3. 从卡片中建立教材概念候选索引：
   - 概念词
   - 所在卡片
   - 卡片类型
   - 上下文摘要
   - 邻近概念
4. 做一个 `evidence_retriever_mvp`：
   - 输入题目 ID。
   - 读取题干、选项、正确答案。
   - 先做字面种子检索，返回候选卡片和候选概念。
   - LLM 基于候选概念生成检索计划。
   - 多路召回教材候选证据。
   - 输出证据候选报告。
5. 用 `2.1_19` 做盲测。
6. 盲测后再打开现有解析、答疑和证据包做对照。
7. 记录漏召回、误召回和需要新增的检索锚点。

第一阶段结束标准：

> `2.1_19` 的关键跨段证据能被检索器召回，且候选数量可控。

## 14. 主要风险

- 只改关键词，不做证据归因，系统仍然会自由发挥。
- 直接改基础图，把题目特定关系误写成教材通用关系。
- 继续依赖现有解析，导致“拿答案解释答案”。
- 卡片检索命中相关词，但无法说明证据用途。
- 召回太多噪声，教研审核成本不降反升。
- 引用审计只查编号存在，不查是否支撑结论。
- 学生答疑阶段过早上线，暴露不可靠回答。
- 只做解答生成，不沉淀学生误解数据，最终退化成普通解析生成器。

## 15. 当前判断

当前最值得做的是 **证据检索器 MVP**。

先不要做完整系统、不要做学生侧 UI、不要继续手工补证据包。先证明：

```text
题干 + 选项 + 正确答案 + 教材
→ 系统能找出教研会用的教材证据
```

这一步跑通后，再做证据归因、推理桥梁和带编号引用的解析/答疑生成。
