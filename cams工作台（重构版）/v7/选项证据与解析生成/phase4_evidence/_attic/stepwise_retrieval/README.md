# 分步检索实验

本目录将检索层实验与生产环境的 Phase 4 代码隔离。每个步骤写入机器可读的 JSON 和一个精简的 Markdown 审查文件。

## 工作流

### s0：P5 术语归一化 + 检索头构建

目录：`s0/`

s0 阶段拆分为多个变体，以便比较搜索前使用 P5 的效果。

#### s0a：P5 归一化检索头

脚本：`s0/s0a_p5_heads.py`

输入：
- v7 题目对象
- P5 别名索引

过程：
1. 将题目拆分为字段：题干、选项_A、选项_B……
2. 逐字段匹配 P5 别名组。
3. 保留原文，附加匹配到的规范术语作为归一化元数据。
4. 从归一化后的字段构建检索头：
   - `stem`（题干）
   - `option_A`、`option_B`…… = 归一化题干 + 归一化选项
   - 可选 `all_options` 兜底

输出：
- `*.s0a.json`：归一化字段、匹配到的 P5 术语、检索头
- `*.s0a.md`：人工可读的审查视图

s0 的非目标：
- 不涉及 BGE/BM25 搜索。
- 不涉及 P5 证据单元召回。
- 不涉及知识图谱扩展。
- 不调用 LLM。

#### s0b：P5 别名展开式检索头

脚本：`s0/s0b_alias_expanded_heads.py`

目的：
- 将 P5 作为窄范围的别名/缩写归一化层。
- 生成配对检索查询，供 s1 比较别名提示是否有帮助。

每个检索头输出：
- `query_original`：仅原始题干/选项文本。
- `query_alias_hints`：所有尚未出现在原文中的 P5 规范术语和别名，供审计。
- `query_expansion_hints`：策略允许的提示，追加到测试查询中。
- `query_broad_hints`：语义有效但过于宽泛的提示，默认不追加。
- `query_suppressed_hints`：已知有噪音的提示，默认不追加。
- `query_expanded`：原文仅加上 `strong` / `retrieval_equivalent` 级别的提示。
- `query_expanded_all_hints`：仅用于检查的查询，附带了所有提示。

策略：
- s0b 中不召回 P5 `evidence_unit_ids`。
- P5 术语不是知识图谱边。
- P5 术语不是答题证据。
- 宽泛提示保持可观察，但不会进入 s1 的默认 `query_expanded`。

#### s0c：P5 规范内联式检索头

脚本：`s0/s0c_canonical_inline_heads.py`

目的：
- 测试内联规范注释是否比仅追加提示效果更好。
- 保留原词，同时原地插入严格的全称注释。

每个检索头输出：
- `query_original`：原始题干/选项文本。
- `query_canonical`：原文加上严格的缩写/全称注释。
- `canonical_inline_hits`：匹配到的术语及插入的注释。

策略：
- 第一版仅对 `abbreviation_full_form`（缩写-全称）做内联。
- 检索等效术语（如 SAR/STR）不做内联。
- 宽泛术语（如 jurisdiction/regulator）不做内联。
- P5 匹配结果仍是查询转换元数据，不是证据。

### s1：基于分层检索头的直接单元召回 A/B 实验

目录：`s1/`

脚本：`s1/s1_direct_unit_retrieval.py`

输入：
- s0a 分层检索头
- s0b 分层检索头
- s0c 分层检索头

A/B 对比定义：
- s0a：原始字段头 vs P5 归一化头。
- s0b：`query_original` vs P5 别名展开的 `query_expanded`。
- s0c：`query_original` vs P5 规范内联的 `query_canonical`。

过程：
1. 默认保留 `stem` 和 `stem + 单个选项` 头。
2. 对每个实验的基线查询和测试查询分别运行。
3. 对每个基线/测试查询，分别运行 BGE、BM25_zh 和 BM25_en 直接单元召回。
4. 按 `unit_id` 合并各路结果以供检查。
5. 报告 P5 展开查询新增或减少的单元。

s1 的非目标：
- 不涉及知识图谱扩展。
- 不调用 LLM。
- 不做答案判定。
- 不涉及 P5 直接单元召回。
- 不将 s0a/s0b/s0c 混入同一个 A/B 结果中。

输出：
- `s1/output/s1_direct_unit_retrieval/s0a/*.s1.s0a.json`
- `s1/output/s1_direct_unit_retrieval/s0a/*.s1.s0a.md`
- `s1/output/s1_direct_unit_retrieval/s0b/*.s1.s0b.json`
- `s1/output/s1_direct_unit_retrieval/s0b/*.s1.s0b.md`
- `s1/output/s1_direct_unit_retrieval/s0c/*.s1.s0c.json`
- `s1/output/s1_direct_unit_retrieval/s0c/*.s1.s0c.md`

### s2：知识图谱扩展实验

目录：`s2/`

s2 是知识图谱扩展研究层。它从 s1 直接单元种子出发，研究知识图谱结构能否在保持噪音可观察的同时扩展有用上下文。

脚本：`s2/s2_kg_expansion.py`

当前脚本是 v0 检查原型，并非最终的 s2 工作流。在作为默认实验重新运行之前，仍需更新策略。

下一版 s2 设计的 s1 种子策略：
- 主种子池：`baseline union s0c`
- 可选补充：`s0b` 新增单元
- 仅诊断用途：`s0a`

扩展层：
- `direct_seed`：将 s1 直接单元保留为根节点。
- `same_core_point`：在种子核心点下添加兄弟单元。
- `related_core_point_edge`：遍历核心点之间可观察的知识图谱边。
- `section_context`：可选同章节上下文；默认关闭。

共同目标：
1. 将检索覆盖范围扩展到直接 BGE/BM25 种子之外。
2. 对每个新增单元保留知识图谱路径。
3. 比较召回增益与噪音风险指标。
4. 保持 `question_id`、`head_id`、直接种子来源、路径、关系、范围、方向可观察。
5. 向 s3 提供候选知识图谱上下文，而非最终证据。

s2 的非目标：
- 不涉及 BGE/BM25 搜索。
- 不调用 LLM。
- 不做答案判定。
- 不将知识图谱扩展的单元视为最终证据。

### s3：检索上下文重排序与渲染

目录：`s3/`

s3 将 s1/s2 的召回内容转换为 LLM 可读的召回文本。

目的：
- 对召回文本进行重排序。
- 组织直接检索和知识图谱扩展的上下文。
- 将单元和路径重新格式化为可读的 Markdown。

s3 的非目标：
- 不涉及 BGE/BM25 搜索。
- 不涉及知识图谱扩展。
- 不调用 LLM。
- 不做答案判定。
- 不生成最终解析。

### s4：盲审判定

目录：`s4/`

s4 读取 s3 的召回文本，让 LLM 做出盲审结构化判定。

目的：
- 仅基于召回内容对每个选项做出判定。
- 输出预测答案、选项级依据、引用单元 ID 和证据缺口。
- 将判定过程与面向学员的解析写作分开。

s4 的非目标：
- 不涉及 BGE/BM25 搜索。
- 不涉及知识图谱扩展。
- 不输入参考答案或参考解析。
- 不生成最终考试风格的解析。

### s5：判定评估

目录：`s5/`

s5 在盲审判定完成后，将 s4 盲审输出与参考答案和参考材料进行对比。

目的：
- 衡量答案一致或冲突的情况。
- 追踪参考来源冲突。
- 检查选项级判定是否与参考材料一致。
- 将参考感知评估与盲审判定分开。

s5 的非目标：
- 不涉及 BGE/BM25 搜索。
- 不涉及知识图谱扩展。
- 不做新的盲审判定。
- 不生成面向学员的解析。

### s6：面向学员的解析生成研究

目录：`s6/`

s6 研究在判定和评估分离之后，如何为学员编写最终解析。

目的：
- 研究解析写作的输入和提示词。
- 决定如何使用 s4/s5 结果、召回文本、参考材料和教学上下文。
- 仅在判定任务隔离后生成最终考试风格的解析。

s6 的非目标：
- 不涉及 BGE/BM25 搜索。
- 不涉及知识图谱扩展。
- 不替代盲审判定。
- 不隐藏 AI 与参考材料的冲突。
