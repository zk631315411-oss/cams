# 脚本说明

这个目录的脚本名字是项目演化过程中留下来的，很多名字偏工程临时命名，不太适合直接理解业务含义。本文档用人话说明每个脚本现在的地位和作用。

## 一句话总览

这个目录负责把“题目、选项、标准答案”与“教材原文句卡”建立关系，产出选项级教材依据、题目证据绑定和候选考点资产。

当前新题解析、学生答疑模块也复用了这里的检索、证据池和 LLM 调用能力。

## 当前主线脚本

### `run_step1.py`

人话名称：题目证据绑定主入口 / 公共运行时基础模块

作用：

- 读取题目、教材句卡、KG 辅助资产。
- 初始化 DeepSeek、BGE、证据池等运行时。
- 提供标准答案题目的证据绑定流程。
- 提供很多公共函数，例如 LLM 调用、答案归一化、状态分类、质量统计。

当前地位：

- 核心保留。
- 新题解析、学生答疑模块也会 import 它。
- 虽然名字像“第一步”，但现在它更像整个证据绑定系统的基础模块。

### `run_agentic_search_experiment.py`

人话名称：Agentic 多路检索与证据裁判核心模块

作用：

- 根据题目和选项生成检索计划。
- 混合召回教材句卡：BGE、关键词、短语、相邻句卡、关系扩展等。
- 对候选证据做裁判，输出选项级证据状态和教材依据。

当前地位：

- 核心保留。
- 新题解析和学生答疑都复用了它的检索能力。
- 名字里有 `experiment`，但它现在已经不只是实验脚本，而是核心检索模块。

### `run_blind_q212_experiment.py`

人话名称：无标准答案盲判流程参考模块

作用：

- 用于探索“不给标准答案，模型自己判断答案”的流程。
- 新题解析模块借用了里面的盲判思路和部分辅助函数。

当前地位：

- 需要保留。
- 名字里有 `q212` 和 `experiment`，确实历史痕迹比较重，但当前仍被新题解析模块引用。

### `run_step2_option_mapping.py`

人话名称：选项级教材依据映射生成器

作用：

- 读取每题的 agentic 结果。
- 生成题目、选项、教材句卡之间的结构化映射。
- 产出类似 `question_option_card_map.json`、`card_option_question_map.json`、`stats.json` 的结果。

当前地位：

- 核心保留。
- 第二章题目证据绑定正式产物来自这一类整理流程。

### `run_parallel_agentic_batch.py`

人话名称：批量跑题调度脚本

作用：

- 按题目批量调用 agentic 流程。
- 支持小并发、分组运行、断点续跑和报告输出。

当前地位：

- 建议保留。
- 后续如果导入更多题目、重跑第二章或扩展章节，会用到它。

## 数据构建脚本

### `build_v6_sentence_cards.py`

人话名称：构建 V6 全书句级教材证据池

作用：

- 从 V6 教材清洗文本中切句。
- 调用 LLM 给每句话生成 `knowledge` 和 `type` 标签。
- 产出全书级句卡，例如 `cards_v6_sentence.json`。

当前地位：

- 建议保留。
- 不是每天运行，但如果教材原文、句卡规则变化，需要它重建证据池。

### `build_ch2_sentence_cards.py`

人话名称：构建第二章句级教材证据池

作用：

- 针对第二章构建句级教材证据卡。

当前地位：

- 建议保留。
- 现在主线更多依赖全书 V6 句卡，但这个脚本可用于追溯第二章早期资产。

### `build_v6_except_ch2_sentence_cards.py`

人话名称：构建 V6 除第二章外的补充教材证据池

作用：

- 为第二章题目补充“第二章以外”的教材证据。
- 解决有些题目虽然属于第二章练习，但依据在全书其他章节的问题。

当前地位：

- 建议保留。
- 对“题目证据可来自全书，但旁注只显示当前阅读页”的设计有追溯价值。

### `build_combined_evidence_pool.py`

人话名称：合并教材证据池工具

作用：

- 合并第二章句卡和第二章外补充句卡。
- 保留每条卡原本的 `evidence_scope`，方便下游判断证据来源。

当前地位：

- 建议保留。
- 重建组合证据池时可能用到。

### `build_exam_point_mapping.py`

人话名称：从选项证据反推候选考点

作用：

- 读取题目证据绑定结果。
- 根据正确选项、教材依据和题目焦点，生成候选考点映射。

当前地位：

- 建议保留。
- 和“考点怎么由题目、选项、解析反推出来”直接相关。

当前地位：

## 如果以后要改名

建议不要直接重命名现有核心脚本，因为新题解析、学生答疑模块会直接 import 它们。

更稳的做法是：

1. 新增更好懂的新文件名。
2. 让旧文件继续存在，作为兼容入口。
3. 逐步把新模块改为 import 新名字。
4. 全部测试通过后，再考虑是否移除旧名字。

目前建议先保留现有文件名，用本文档降低理解成本。
