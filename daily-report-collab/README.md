# 日报协作助手

## 简介

这个 Skill 解决一个实际问题：**每天写日报太烦了，但又不得不写。**

核心思路是"自动采集 + 人工补充"——

- **自动采集**：扫描工作区下所有 git 仓库，提取今日提交记录（作者、时间、消息、涉及文件）
- **人工补充**：用提问方式让你补充上下文、困难点、明日计划等机器无法知道的信息
- **输出**：日报 / 周报 / 交接文档，按模板渲染成可直接粘贴的格式

不需要打开多个终端查 log，也不需要回忆今天改了哪些文件。交给它做，你只负责补充"为什么"和"然后呢"。

## 安装方式

### 方式一：放入 skills 目录（推荐）

将 `daily-report-collab/` 整个目录复制到 opencode 的 skills 目录：

```
.opencode/skills/daily-report-collab/
```

opencode 会自动加载。

### 方式二：直接引用

在 `opencode.json` 中配置 skills 路径指向本目录。

## 使用方式

### 触发

在工作区中对 AI 说任意一句：

- "生成日报"
- "帮我写周报"
- "要交接了，生成交接文档"
- "恢复一下上下文"

AI 会自动加载此 Skill 并进入工作流程。

### 交互流程

```
STEP 1 → AI 提问：你想生成什么？（日报/周报/交接文档/日报+交接文档）
           + 你的工作区路径是什么？

STEP 2 → AI 扫描工作区下所有 git 仓库，提取今日/本周提交记录

STEP 3 → AI 提问：补充人工信息（困难点、明日计划、未完成事项等）

STEP 4 → AI 按模板渲染，输出最终文档
```

如果之前设置过工作区路径，会自动跳过 STEP 1 的路径提问。

## 设计思路

### 为什么 git 采集 + 人工输入要结合？

纯自动生成的日报缺乏"上下文"——机器知道你改了哪些文件，但不知道你为了解决什么问题改的、遇到了什么坑、下一步打算怎么做。纯人工写又太累，而且容易遗漏改过的文件。

结合的好处：**git 提供事实清单，人提供叙事线索。** 事实 + 叙事 = 一份合格的日报。

### 为什么用 PowerShell 而不是 bash？

团队使用 Windows 环境，PowerShell 是原生 shell，不需要安装 WSL 或 Git Bash。`git log` 的输出格式在 PowerShell 中可以通过 `--format` 参数稳定解析，而且 PowerShell 对中文路径和 UTF-8 的支持比 cmd 好。

如果未来有跨平台需求，可以再加一个 `git_today_commits.sh`。

### 为什么模板用占位符设计？

不同项目的日报格式可能不一样（有的要写"风险点"，有的要写"评审状态"）。占位符模板的好处：

- **不改逻辑只改模板**：格式变动不碰脚本，改 markdown 文件即可
- **可复用**：同一个人在不同项目间切换，换模板就行
- **可版本控制**：模板文件可以进 git，每次改格式都有记录

占位符格式统一为 `{{PLACEHOLDER_NAME}}`，渲染时替换。
