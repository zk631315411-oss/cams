# CAMS 正式工作台：实习生项目导览

这是一个把 CAMS 新题从题源整理推进到可追溯发布的工作台。这里不只保存答案，还保存证据、解析版本、核验结果、人工决定和每次操作记录。

## 一道题怎样流转

```text
接收整理 -> 重复检查 -> 证据研究 -> 证据确认
         -> 正式解析 -> 最终核验 -> 教研批准 -> 发布
```

- Codex 负责读取题目、检索和登记证据、整理候选、生成解析版本及最终核验。
- 教研在网页确认证据、提交解析批注并作最终决定。
- DeepSeek 只在教研同意时提供第二意见，不是必经步骤。
- 所有正式写入都留下审计记录，任何旧版本都不能静默覆盖新版本。

## 先认识目录

| 目录 | 可以把它理解成 |
| --- | --- |
| `frontend` | 浏览器里的证据审阅台 |
| `backend` | API、MCP、检索、存储和规则 |
| `data` | 教材、索引和每道题的长期档案 |
| `runtime` | BGE-M3 等本地运行资源 |
| `scripts` | 安装、启动和交付工具 |
| `tests` | 防止关键规则被改坏的自动检查 |
| `releases` | 已批准内容的不可变发布快照 |
| `docs` | 当前契约和交接状态 |

## 单题档案

每道题位于 `data/questions/<question_id>/`。常见文件包括：

- `question.json`：当前题面、内容版本和档案修订号。
- `workflow.json`：V2 正式阶段和版本引用，是流程权威记录。
- `task_state.json`、`task_history.jsonl`：Codex 当前任务和历史。
- `retrieval_runs.jsonl`、`evidence_catalog.json`：检索轮次与去重证据库。
- `evidence_candidates.jsonl`、`evidence_confirmation.json`：Codex 候选和教研确认。
- `analysis_versions.jsonl`、`analysis_feedback.jsonl`：正式解析版本与批注。
- `final_checks.jsonl`、`decision.json`：最终核验和教研决定。
- `audit.jsonl`：不可覆盖的操作记录。
- `source/`：题源原件和历史迁移材料。

文件按流程逐步生成，不是每道题都会同时拥有全部文件。迁移题还可能保留旧 DS、旧核验或 `evidence_review.json`，这些只能作为历史兼容材料。

## 开发时先记住

1. 不要直接修改 `data/questions`；使用 API、MCP 或 `WorkspaceStore`。
2. 不要用 `question.status` 判断 V2 阶段；读取 `workflow.json`。
3. 不要把检索候选当作已确认依据；正式解析只能使用教研确认的证据版本。
4. 不要把模型文件存在当作检索可用；当前 BGE-M3 真实加载仍有已知故障。
5. 不要把旧 DS 接口继续扩展为主线；它们待确认调用者后删除。

这份文档只提供入门地图。具体契约以同目录的 API、MCP、数据、工作流和检索文档及实际代码为准。
