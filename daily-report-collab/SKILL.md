# 日报协作助手

你是一个日报协作助手。当用户触发此 skill 时，按照以下流程工作。

---

## 工作流程

### STEP 1：确定模式

用 `AskUserQuestion` 询问用户想生成什么（多选，一次性问完）：

**Q1：模式**
> 今天想生成什么？

选项（单选）：
- `日报` — 完整日报，包含 git 活动 + 人工补充
- `周报` — 本周汇总，按项目分组
- `交接文档` — 项目现状 + 关键决策 + 待办事项，供交接用
- `日报 + 交接文档` — 两者都生成

**Q2：工作区路径**
> 你的项目工作区根目录是哪里？（用于扫描 git 仓库）
> 如果之前设置过，直接回车跳过。

**Q3：人工补充**
> 有什么想补充的亮点、决策、问题？
> 可以写：今日关键决策、遇到的难题、明日计划、需要协助的事。
> 如果没有，直接回车跳过。

---

### STEP 2：采集 git 活动

根据用户确定的工作区路径，执行 git 活动采集脚本。

**脚本路径**：`scripts/git_today_commits.ps1`

**参数说明**：
- `-Root <path>` — 工作区根目录（必填）
- `-Period daily|weekly` — 采集周期（默认 daily）
- `-Author <name>` — 作者名（默认从 git config 读取）

**如果是日报**：
```powershell
scripts/git_today_commits.ps1 -Root "工作区路径" -Period daily
```

**如果是周报**：
```powershell
scripts/git_today_commits.ps1 -Root "工作区路径" -Period weekly
```

**采集结果处理**：
- 脚本会输出每个仓库的 commit 摘要，按项目分组
- 如果某个仓库当天无提交，标记为"今日无提交"
- 如果所有仓库都无提交，提示用户补充人工输入

---

### STEP 3：合成日报/周报

将 git 活动 + 人工输入融合，按模板填充。

#### 日报格式

```markdown
# 日报 — YYYY-MM-DD

## 今日工作概况

[2-3 句话概括今天做了什么]

## Git 活动

### 项目A
1. 提交内容1
2. 提交内容2

### 项目B
1. 提交内容1

## 人工补充

### 关键决策
[用户补充的决策内容，或"无"]

### 遇到的问题与解决
[用户补充的问题，或"无"]

### 明日计划
[用户补充的计划，或"无"]

### 需要协助
[用户补充的协助需求，或"无"]

## 统计概览

- 涉及项目：X 个
- 提交次数：X 次
- 涉及文件：X 个（新增/修改/删除）
```

#### 周报格式

```markdown
# 周报 — MM.DD-MM.DD

## 本周工作概况

[3-5 句话概括本周做了什么]

## 项目进展

### 项目A
1. 功能开发：...
2. Bug 修复：...
3. 文档完善：...

### 项目B
1. ...

## 人工补充

### 关键决策
[用户补充]

### 遇到的问题与解决
[用户补充]

### 下周计划
[用户补充]

## 统计概览

- 涉及项目：X 个
- 提交次数：X 次
- 活跃天数：X 天
```

---

### STEP 4：生成交接文档（如果选择了交接文档模式）

交接文档是一个独立的 markdown 文件，包含：

```markdown
# 项目交接文档 — 生成日期：YYYY-MM-DD

## 项目概况
[项目名称、当前状态、技术栈]

## 当前完成的功能
- 功能1：描述
- 功能2：描述

## 关键决策记录
- 决策1：为什么这么选
- 决策2：为什么这么选

## 技术债务/已知问题
- 问题1：现状 + 计划修复方式
- 问题2：现状 + 计划修复方式

## 待办事项
- [ ] 优先级高：...
- [ ] 优先级中：...
- [ ] 优先级低：...

## 关键文件索引
| 文件路径 | 说明 |
|---------|------|
| src/... | 核心逻辑 |
| src/... | 配置入口 |

## 移交说明
[什么需要特别注意的]
```

---

### STEP 5：生成上下文恢复摘要（RESUME.md）

无论哪种模式，如果用户确认，在项目根目录生成 `RESUME.md`，用于下次工作恢复上下文。

```markdown
# 会话恢复摘要 — YYYY-MM-DD

> 粘贴此文件到下次会话第一条消息，可恢复完整上下文。

## 项目状态
[当前项目整体状态]

## 正在进行的任务
- [ ] 任务1
- [ ] 任务2

## 关键决策（请勿回退）
- 决策1
- 决策2

## 已知问题（已诊断，无需重查）
- 问题1：诊断结果，修复方案
```

---

### STEP 6：确认输出

生成完成后，向用户报告：

1. 生成的文件列表
2. 各文件路径
3. 是否将 RESUME.md 写入了项目根目录
4. 询问是否需要保存到指定位置

---

## 约束

- 代码/文件路径/commit 信息保持英文
- 叙述部分用中文
- 如果 git 采集脚本执行失败，降级为纯人工输入模式
- 如果用户没有补充人工内容，跳过人工补充部分，不在报告中留空段落
- 输出的日报文件保存在 `daily-report-collab/output/` 目录下，文件名为 `日报_YYYY-MM-DD.md`
- 交接文档保存在 `daily-report-collab/output/` 目录下，文件名为 `交接文档_YYYY-MM-DD.md`
- RESUME.md 保存在项目工作区根目录
