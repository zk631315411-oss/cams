# 教材知识图谱建设计划

## 最终目标

建设一个 CAMS 教材知识图谱。教研拿到一道新题，题干和每个选项往图里查：

- 每个选项落到图上的知识节点
- 节点之间有边连着——这些边是概念之间的客观关系
- 教研看图上的分布和连线，直接理解这道题考了什么、选项之间是什么关系

**验收标准**：不是准确率，是三个"能"：
1. 选项能落到节点上（教材没讲的可以落空，落空也是信息）
2. 节点之间的边能说清关系
3. 教研看一眼图谱就懂这道题

## 铁律

1. **旧解析、教研答疑、人工证据包绝不作为输入**。只能用于事后验证。
2. **教材原文可以全量用**。教材全文、目录、卡片——教材自身的材料，不是教研智力产出。
3. **每一步的 LLM 输出驱动下一步**。不人手写分析结论塞进 prompt。
4. **节点和边不人工编造**。人可以审核、删、改，但不能替 LLM 写。
5. **每条推理必须有 card_id**。可追溯是底线。
6. **教研数据只验证，不参与构建**。验收不通过回去改图，不反向喂数据。
7. **过程可审计**。每次 LLM 调用的 prompt 和输出都保存。任何节点、边都能追溯到来源。

## 核心思路

**节点来自教材目录，边来自 LLM 读全文。** 借鉴数学知识图谱项目（`D:/ai math`）的物理骨架+知识边分层架构：

- **节点**：教材目录的小节标题。"税收损失""声誉风险""削弱金融组织"——目录里本来就有。不需要 LLM 提取。每个节点有 definition（LLM 概括）和挂载卡片（BGE 匹配）。
- **边**：跨小节概念之间的**客观关系**。LLM 一次性读教材全文后标注——主体不同、方向相反、属于同一流程的不同阶段等。一次性产出，所有题复用。
- **查询**：选项文本 → BGE 匹配节点 → 沿边遍历 → 拿到关联节点的卡片 → 形成推理链。

"易混淆"不是预设标签。教研拿到题，把选项往图上一放，D 落在"税收损失"、A 落在"FI后果"，两个节点之间的边自然解释了学生会怎么错。

## 第一步：LLM 读全文，标注跨节关系（边）

### 1.1 输入

- 教材第2章全文（`ch2_full_text.txt`，~87,000 字符）
- 教材目录（`toc_ch2_compact.txt`，小节标题列表）

### 1.2 做法

LLM 一次性读教材第 2 章全文，用 v4-pro 模型，temperature=0.05。

LLM 拿到两样东西：教材目录（告诉它有哪些小节节点）+ 教材全文（让它理解每个小节的内容）。

LLM 的任务不是提取概念节点——节点就是目录里的小节。LLM 的任务是：**找出哪些小节之间存在有意义的关联，标注关系类型和依据。**

### 1.3 Prompt 模板

```
你是CAMS教材的教学设计专家。以下是教材第2章的目录和完整原文。

【教材目录】
{toc}

【教材全文】
{textbook}

你的任务：

一、为每个小节写一句 definition（从教材原文概括，不超过30字）。

二、找出小节之间存在有意义的关联。关联必须是客观的教材层面的关系，例如：
- 主体不同：两个小节讨论的是同一个现象对不同主体的影响
- 方向相反：两个小节对同一件事的结论方向相反
- 同属流程：两个小节是同一个流程/机制的上下游步骤
- 概念层级：一个小节是另一个小节的下位概念
- 互为因果：一个小节的原因和另一个小节的结果存在对应关系
- 其他（需在relation_detail中说明）

注意：
- 只标注教材中确实存在的关系，不臆造
- 两个小节可能有多条边（不同类型的关联）
- 不是每对小节都必须有关联，没有关联就跳过
- 标注的是"两个知识点之间的客观关系"，不是"学生会不会搞混"

输出JSON（不要markdown包裹）：
{
  "sections": [
    {
      "section_id": "2.1",
      "subsection_title": "小节标题",
      "definition": "一句话概括"
    }
  ],
  "edges": [
    {
      "from_section": "2.1",
      "from_subsection": "税收损失",
      "to_section": "2.1",
      "to_subsection": "削弱金融组织",
      "relation_type": "主体不同",
      "relation_detail": "税收损失的主体是政府（政府税收缩水），FI后果的主体是金融机构（盈利业务流失等），两者都涉及洗钱的经济影响但承受主体不同",
      "key_cards_hint": ["税收缩水", "盈利业务流失", "代理银行业务终止"]
    }
  ]
}
```

### 1.4 验收标准

| # | 验收项 | 标准 | 验证方式 |
|---|---|---|---|
| 1.1 | 小节覆盖 | 目录中所有小节都有 definition | 统计 |
| 1.2 | definition 完整 | 每个小节 definition 非空 | 自动检查 |
| 1.3 | 边总数合理 | 15-60 条（太少漏关联，太多说明噪声） | 统计 |
| 1.4 | 关键边存在 | (税收损失) — (削弱金融组织) 的边必须存在，relation_type 为"主体不同"或等价 | 精确检查 |
| 1.5 | 每条边有依据 | relation_detail 非空，引用了教材中的具体内容 | 自动检查 |
| 1.6 | 无编造 | 随机抽 5 条边，在教材原文中找到支撑 | 人工抽检 |

## 第二步：卡片→节点挂载

### 2.1 输入

- 第一步产出的节点表（`sections.json`，含每个小节的 definition）
- 1950 张卡片（`cards_ch2.json`）

### 2.2 挂载算法

两路并进，确定性优先：

**路A：citation 直接匹配（确定性）**

- 卡片的 `citation` 字段包含了它在教材中对应的原文引用
- 将 citation 文本与每个小节的教材原文做字符串包含匹配
- 匹配到的卡片直接挂到对应小节，不走 BGE
- 这是确定性关系，不受向量相似度波动影响

**路B：BGE 搜索（兜底）**

- 对 citation 匹配失败的剩余卡片，用 BGE 全量搜索
- 预计算剩余卡片的 `knowledge` 字段 BGE 向量并缓存
- 对每个节点，query = `subsection_title + " " + definition`，编码为 BGE 向量
- 做余弦相似度排序，取 top-3，筛掉 score < 0.5 的

**阶段C：合并去重**

- 路A 和 路B 的结果合并
- 同一张卡被多个节点匹配时，路A 的优先级高于 路B。同路内的按相似度排序，递补

### 2.3 输出格式

```json
{
  "card_to_section": {
    "v6_b04_N09": {"section": "削弱金融组织", "section_id": "2.1", "score": 0.92},
    "v6_b03_N18": {"section": "税收损失", "section_id": "2.1", "score": 0.88}
  },
  "section_to_cards": {
    "削弱金融组织": ["v6_b04_N09", "v6_b04_N10", "v6_b04_N11"],
    "税收损失": ["v6_b03_N18", "v6_b03_N19", "v6_b03_N20"]
  }
}
```

### 2.4 验收标准

| # | 验收项 | 标准 | 验证方式 |
|---|---|---|---|
| 2.1 | v6_b04_N09 挂对 | 挂在"削弱金融组织"节点下 | 精确检查 |
| 2.2 | v6_b03_N18 挂对 | 挂在"税收损失"节点下 | 精确检查 |
| 2.3 | 挂载率 | ≥80% 的节点至少有 1 张卡挂载（score≥0.5） | 统计 |
| 2.4 | 无重复挂载 | 同一张卡不挂在两个不同节点下 | 自动检查 |
| 2.5 | 挂载质量 | 随机抽 5 个节点，人工检查 top-1 卡片是否相关 | 人工抽检 |
| 2.6 | 选项→节点预验证 | 用 2.1_19 的五个选项文本做 BGE 节点匹配：A→削弱金融组织，D→税收损失，E→削弱金融组织，C 落空或低分。如关键匹配失败，不进入第三步 | BGE 匹配 + 人工确认 |

## 第三步：端到端验证（用 2.1_19）

### 3.1 验证流程

**步骤1：选项→节点定位**

输入：D 选项文本"公司税的增加"

方法：
- 用 BGE 将选项文本与所有节点的 `subsection_title + " " + definition` 拼接文本做余弦相似度
- 取 top-3 匹配节点

通过标准：top-3 中包含"税收损失"节点。

**步骤2：节点→卡片**

- 从"税收损失"节点的挂载卡片中，检查是否包含 v6_b03_N18 或 v6_b03_N19

通过标准：挂载卡片中包含 v6_b03_N18 或等价卡。

**步骤3：关联边检查**

- 检查"税收损失"节点出发的边中，是否有连接"削弱金融组织"或 FI 后果相关节点的

通过标准：存在至少一条边连接税费概念与 FI 后果概念，边有明确的 relation_type 和 relation_detail。

**步骤4：推理链生成**

- LLM 输入：选项 D 文本 + 步骤 1-3 的结果
- LLM 输出：一句话推理链，包含 card_id 引用

通过标准：推理链包含"主体错配""税收损失≠公司税增加""政府税收缩水而非 FI 公司税增加"三者之一。

**兜底**：步骤 1 top-3 中不包含"税收损失"时，用 LightRAG 兜底搜索。搜到 v6_b03_N18 也算通过。

### 3.2 验收总表

| # | 验收项 | 通过标准 |
|---|---|---|
| 3.1 | D 选项节点定位 | top-3 中包含"税收损失"，或兜底搜索命中 v6_b03_N18 |
| 3.2 | 卡片检索 | 挂载卡片或兜底搜索中包含 v6_b03_N18/v6_b03_N19 |
| 3.3 | 关联边 | 存在税费↔FI后果的边，有 relation_type 和 relation_detail |
| 3.4 | 推理链结论 | 包含主体错配/税收损失≠公司税增加/政府税收缩水 |
| 3.5 | 推理链引用 | 引用的 card_id 确实存在 |
| 3.6 | 端到端全通 | 3.1-3.5 全部通过 |

## 执行顺序

1. **第一步**：教材第2章全文 → LLM 标边 → 验收 1.1-1.6 → 产出 `sections.json` + `edges.json`。这一步本身就是试点——全章一次跑。验收不通过不进入下一步
2. **第二步**：卡片挂载 → 验收 2.1-2.5 → **追加验证：用 2.1_19 五个选项做 BGE 节点匹配**，检查 A/E→削弱金融组织、D→税收损失、C→落空。如果关键选项匹配失败，不进入第三步
3. **第三步**：2.1_19 推理链验证 → 验收 3.1-3.6 → 产出 `validation_report.md`

## 数据分层

```
kg_data.json           ← 冻结的知识图谱（节点、边、卡片挂载），构建完成后只读
question_section_map.json ← 查询层（题目选项→节点映射），独立加载，可追加
```

- 图谱是图谱，映射是映射。两个文件，两个职责。
- 前端分别 fetch，不合并。
- 图谱构建阶段结束即冻结，后续只追加映射表。

---

## 与教研的接口

- 节点（小节）→ 教研可以修改 definition
- 边 → 教研可以增删、修改 relation_type 和 relation_detail
- 卡片挂载 → 教研可以手动调整
- 所有自动生成的数据都是"建议"，最终由教研确认
