## 教研5/30上线反馈（完整）

1. **颜色花花绿绿**，不如原型HTML清晰
2. **跳转最好是自动跳转**，不需要额外点"定位原文"
3. **右侧题目关联只是关键词匹配**，没有真正定位到考点——这是核心问题
4. 左边标黄太密，原版是定位精炼的考点概念再附样式
5. 切换时滚动晃眼

## 5/30 深入讨论后的发现

| 环节 | 发现 |
|---|---|
| 题目→卡片匹配 | AI做的关键词匹配 ≠ 教研的考点归因。教研是从答案+解析出发倒推"这题考哪个知识点" |
| 我的工作方式 | 自己也在用关键词grep读教材，批评匹配脚本是关键词撞库，自己也是 |
| CLAUDE.md | 加了"每次调工具前解释意图"规则和杠精角色 |
| 题1分析 | 用Bloom六层看，题1考的是分析层（从FATF+EU指令推出"一致监管"目的），不是记忆层 |
| 核心洞察 | 教研的归因是**证据链推理**——每道题是从教材多段材料中拼出逻辑链 |
| 她的真实需求 | "帮助我发现哪些考点题多/答疑多/学生容易误解/适合做专题"——她要教学诊断仪表盘，不是内容浏览器 |

## 5/30 答疑分析

| 发现 | 细节 |
|---|---|
| 学生提问模式 | 几乎全是"为什么选A"，要推理过程不要答案 |
| 教研回答模式 | 核心考点→教材依据→选项分析→结论，格式不统一但结构类似 |
| 教研+Codex协作 | 解析是和Codex协作写的，她审过。Codex帮她写结构，她做"该去哪找依据"的判断 |
| 我的demo翻车 | 我想写AI答疑生成器，但教研+Codex已经做得比我好——我不该跟已有的工作流竞争 |
| 我应该做什么 | 帮她看到Codex看不到的东西——全局数据：哪些考点答疑集中、哪些解析最弱 |

## 从时间线看规律

1. **教研的需求一直在澄清，没有变来变去**。从第一天的"显示完整题干"到最后"帮我发现哪些考点适合做专题"，是一条线——她要的不是更漂亮的浏览器，是能从数据中做决策。
2. **我总是在被反馈之后才改方向，没有预先对齐**。一周做了9个功能模块，没有一个是在做之前问过"你确定这个对吗"。
3. **唯一没被批评的是数据管线**——parse_questions、parse_qa、build_chapter——因为那些是地基，教研看不到但必须有。
