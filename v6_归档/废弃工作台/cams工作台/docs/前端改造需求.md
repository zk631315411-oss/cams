## kg_data.json 结构

这是本次改造的核心数据源。结构如下：

```json
{
  "v6_b04_N09": {                          // key = card_id
    "section": "削弱金融组织",              // 这张卡属于哪个概念节点
    "edges": [                              // 该节点的关联边
      {
        "target": "税收损失",               // 关联到的另一个概念节点
        "type": "主体不同",                 // 关系类型
        "detail": "税收损失讨论的是政府税收缩水……FI后果讨论的是金融机构……承受主体不同"
      }
    ]
  },
  "_sections": {                            // 所有概念节点的元数据
    "税收损失": {
      "definition": "洗钱使政府税收缩水，间接危害纳税人",
      "aliases": ["PEP"],                   // 别名（英文缩写等）
      "card_count": 15                      // 该节点挂载的卡片数
    }
  },
  "_edges": [                               // 所有边的摘要
    {"from": "税收损失", "to": "削弱金融组织", "type": "主体不同", "detail": "……"}
  ],
  "_hybrid_results": {                      // 6道题验证结果
    "2.1_19": {
      "method": "fallback",                 // 用图谱还是兜底
      "chain": "D选项'公司税的增加'反映的是政府税收损失……主体错配"
    }
  }
}
```

**关键：** 每个 `card_id` 通过 `section` 字段连接到概念节点，概念节点之间通过 `edges` 关联。教研点击一张卡片，前端应该展示它所属的节点、以及这个节点关联的其他节点。

## 核心功能需求

### 1. 卡片→概念节点→关联节点

- 用户点击教材中的卡片（或通过搜索/题目选中卡片）
- 展示这张卡属于哪个**概念节点**（section 名称 + definition）
- 展示这个节点通过哪些**边**连接到哪些其他节点
- 边的展示要包含：目标节点名、关系类型（主体不同/方向相反/互为因果等）、关系详情
- 点击关联节点可以跳转到对应卡片

### 2. 题目查看

- 显示 179 道题目列表
- 点击题目显示：题干、ABCD 选项、正确答案
- 最好能展示每个选项落到图上的哪个概念节点（这个映射在 `_hybrid_results` 里有 6 道题的示例，全量映射表在 `data/agentic_search_eval_v2/kg/question_section_map.json`）

### 3. 搜索

- 按考点名、题目关键词、卡片内容搜索
- 搜索结果可点击跳转

## 教研的偏好（重要！）

摘自教研原话：

1. **"颜色花花绿绿，不如原型HTML清晰"** — 颜色收敛，用灰白为主，最多一两个强调色
2. **"工作台要做减法"** — 操作简单，不要多余的动画和弹窗
3. **"跳转功能最好是自动跳转，不需要额外点'定位原文'"** — 点击能直接到位置
4. **"左侧标黄太密"** — 高亮应该精炼，不要大片划词

总结：**清爽、克制、信息密度适中。宁可留白多，不要堆满屏。**

## 技术栈建议

- 纯 HTML/CSS/JS，不引入框架（保持和现有部署一致）
- `reader.html` 用了 Tailwind CSS CDN（`modao.cc` 的），可以继续用
- 数据全量加载到内存（本地文件 fetch，没有后端 API）
- BGE embedding 模型太大，前端跑不了——搜索用简单的字符串匹配即可
