# 21 篇 PDF 子代理联合精读总结

生成方式：三个子代理独立阅读，分别覆盖通用流程/程序知识、工业/医学、建筑/法律论文。子代理只获得“理解文本如何提取流程、规则和多跳知识”这一大方向，没有获得统一总结模板或预设结论。

本文区分：

- **论文事实**：论文明确描述的方法、数据、结果或局限；
- **【LLM推理】**：三个子代理或主代理依据多篇论文迁移到 P7E 的判断，不是单篇论文的原结论。

## 一、三个子代理独立形成的共同结论

三组论文虽然来自不同领域，但独立总结自然收敛到下面的管线：

```text
文本/card
  -> mention或候选节点发现
  -> 实体、共指和同义表达归并
  -> 高召回候选关系发现
  -> 条件、动作、情境和结果的语义裁决
  -> 中间流程图/动作图/知识图谱/形式规则
  -> 确定性约束或实例执行验证
  -> 人工复核
```

共同认识包括：

1. 没有一组论文证明“全文一次生成完整流程图”足够可靠。
2. 上游漏节点会直接造成下游漏边；只提高关系分类精度不能解决流程完整性。
3. 条件、例外、替代路径、汇合、事件和情境不能全部压进一条普通 `A -> B` 边。
4. 多跳知识既包括动作顺序，也包括“若干条件共同成立 -> 触发判断/情境 -> 执行动作 -> 产生状态/结果”。
5. 自动字符串匹配、向量相似或接口名称一致只能产生候选，不能证明桥接成立。
6. 原文直接抽取与模型补出的隐含节点必须分层保存。
7. 格式正确不等于图事实正确；必须检查节点端点、条件、可达路径和实例执行结果。
8. `unknown`、`warning`、`review_required` 是必要状态，不能把模型无法判断强制转换为成立或不成立。

## 二、通用流程与程序知识：8 篇

### 01 Friedrich et al. (2011)：文本到中间世界模型再到 BPMN

这是早期较完整的“文本 -> 中间语义模型 -> BPMN”系统。

- 语言难点被分为句法表达差异、动作原子性、内容相关性和跨句指代。
- 中间 `World Model` 包含 `Actor / Resource / Action / Flow`，对象保留来源句子和词语。
- 句子层抽取动作、参与者和对象；文本层处理代词、条件词、并行词、异常词及前向/后向引用。
- BPMN 的节点、边、网关、起止事件、泳道和数据对象由确定性规则生成。
- 在 47 组文本—模型上平均图相似度约为 76.98%。系统容易比人工模型产生更多节点和边。
- 主要错误来自解析噪声、抽象粒度不同、词典不足和文本不按流程顺序叙述。

**【LLM推理】** 对 P7E 最重要的是可追溯中间图，而不是旧式 NLP 规则。新增 flow node 应先进入中间表示，再由程序校验后写入最终图。

### 02 Bellan et al. (2021/2023)：十种流程抽取方法的系统比较

- 区分一步转换 `text -> model` 与两阶段转换 `text -> world model -> process model`。
- 两阶段方法可以分别处理去噪、共指、实体、关系及结构上必要但文本未明确写出的节点。
- 六个可运行工具的比较显示，没有工具在活动、参与者、对象、网关和 Flow 上全面优秀。
- Flow 通常精度较高但召回偏低，即生成的边较可信，但真实边漏得多。
- 主要瓶颈是数据覆盖、规则泛化、评价不统一和缺少共享中间表示。
- 作者提出知识图谱可作为共享中间表示。

**【LLM推理】** P7E 应把候选召回、语义裁决和最终建图分别评价；只检查最终 Draw.io 是否能打开会掩盖漏桥。

### 03 Bellan et al. (2022)：PET 流程抽取数据集

PET 的实体类型包括：

- `Activity`
- `Activity Data`
- `Actor`
- `Further Specification`
- `XOR Gateway`
- `AND Gateway`
- `Condition Specification`

关系包括：

- `Uses`
- `Actor Performer`
- `Actor Recipient`
- `Further Specification`
- `Same Gateway`
- `Flow`

`Same Gateway` 用于把跨句的 `if / otherwise` 归并为同一判断点。`Flow` 同时连接活动、网关和条件节点。

- 数据集有 45 篇流程描述、413 个句子。
- 实体标注一致性 F1 约 0.85，关系约 0.81。
- 使用人工正确实体时，关系基线 F1 可达约 0.90；换成自动实体后降至约 0.61。

这说明关系模型未必不会判断，而是上游没有找到正确节点时，后续根本没有机会恢复真实边。

### 04 Neuberger et al. (2023)：mention、实体归并和关系抽取

论文把任务拆成：

1. Mention Detection：文本出现了什么；
2. Entity Resolution：不同说法是否指同一业务实体；
3. Relation Extraction：实体之间是否存在有向关系。

- 作者为 PET 增加 163 个多 mention 实体簇。
- Actor 跨 mention 平均跨度约 55 token，Activity Data 约 32 token，说明关键关系常跨越较长文本距离。
- CRF 抽 mention，神经模型做共指归并，CatBoost 判断关系。
- 关系候选使用类型、token 距离、句子距离和邻近类型特征，并对大量负样本做采样。
- 神经 Entity Resolution F1 约 0.52，词面匹配仅约 0.26。
- 使用正确上游输入时，机器学习关系抽取 F1 约 0.82；端到端后跌至约 0.31。
- Flow 两端距离超过约 33 token 后，错误概率明显增加。

**【LLM推理】** 全书 P7E 应先利用接口、主体、对象、状态、共指和局部上下文召回候选，再调用昂贵模型裁决。不能只靠接口字符串相等，也不能全量两两比较。

### 05 Neuberger et al. (2024)：LLM 结构化分阶段抽取

- Prompt 分为 Context、Task Description 和 Restrictions。
- LLM 依次做 mention 检测、实体归并和关系抽取，不一次生成整图。
- BPMN 仍由确定性算法构建：合并条件与网关、创建顶点、连接边。
- 在 PET 上，3-shot 的 mention、实体归并和关系 F1 分别约为 0.74、0.74、0.89。
- 去掉格式示例时，mention F1 下降约 0.22。
- 去掉实体/关系定义也会明显降低性能。
- 将一个大任务拆为多个专门抽取任务，mention 和关系 F1 均提高约 0.08。
- Persona 和泛化背景说明贡献较小；1-shot 通常是较好的成本—效果平衡点。
- 即使关系 F1 较高，生成 BPMN 仍会出现 actor 分配和布局错误。

**【LLM推理】** P7E 值得复用的是“明确类型 + 正反例 + 严格 schema + 分任务抽取 + 确定性组图”，而不是一个超长 Prompt。

### 06 Carriero et al. (2024)：程序知识图谱与隐含步骤

其本体包括：

- `Plan`
- 通过 `precededBy / nextStep` 排序的 `Step`
- `Action`
- `Direct Object`
- `Equipment`
- `Temporal Entity`

方法采用两个 one-shot Prompt：先从带噪文本抽取步骤、动作、对象、设备和时间，再依据映射示例生成 RDF/Turtle。

- 单个大 Prompt 同时保证内容正确和 RDF 合法较困难，两阶段更稳定。
- 提供完整大本体反而可能导致漏三元组，一个准确映射示例更有效。
- 180 人 A/B 评价中，抽取质量中位数 4/5，实际有用性中位数 3/5。
- 人工之间对步骤切分和隐含知识也有明显分歧。
- LLM 和人类都会补出文本未明说的设备。
- 高风险工业场景仍要求 human-in-the-loop。

**【LLM推理】** 可以补最小隐含步骤，但必须标记 `llm_inferred`；“看起来合理”不等于可以直接执行。

### 07 Busch et al. (2023)：BPM 提示工程研究议程

这不是完成的抽取系统，而是对提示工程在 BPM 中的潜力和风险进行归纳。

- 潜力包括低数据需求、自然语言交互、跨任务复用和解释性。
- 挑战包括非线性流程的 Prompt 表达、上下文长度、模型选择、跨模型不稳定、后处理和模板评价。
- 论文明确指出，大流程不应把完整 XML 或全部事件日志塞入 Prompt，而应选择与当前任务相关的局部结构。

**【LLM推理】** P7E 的模型上下文单位应是“候选桥接邻域”，全局图由程序累计和校验。

### 08 Dagdelen et al. (2024)：复杂科学知识到嵌套 JSON

- 传统 NER 加两两关系难以表达复杂 n 元和层级关系。
- 作者让 LLM 按用户定义的嵌套 JSON schema 联合抽取实体、关系和分组。
- GPT-3/Llama-2 使用约 400 至 650 个标注样本微调。
- 核心实体作为 JSON 根，其描述、结构和用途作为嵌套属性，实质上形成高阶关系。
- 严格字符串匹配会低估语义正确率；某应用关系 exact-match F1 约 0.537，人工语义评价约 0.832。
- 中间模型预标、专家修正的闭环可把单篇标注时间减少约 57%。
- 作者区分“有原文依据的标准化改写”和“原文没有的信息幻觉”。
- 长输出仍可能导致 JSON 截断，因此解析和 schema 校验不可省略。

**【LLM推理】** “情境 S、对象 O、条件 C 下，出口 A 连接入口 B”属于高阶关系，应使用关系节点或结构化 flow-edge，而不是只保存一段自然语言。

## 三、工业与医学：6 篇

### 11 Vaucher et al. (2020)：化学文本到结构化动作序列

- 先定义 `Add`、`Wait`、`SetTemperature`、`Filter`、`CollectLayer` 等带属性槽的动作类型。
- 将实验文本视作源语言、动作序列视作目标语言，用 Transformer seq2seq 转换。
- 模型会恢复有限隐含步骤。例如“有机层用硫酸钠干燥”可能隐含先分相和收集有机层。
- 规则系统先生成约 405 万句对，去重后约 276 万；再用 1764 个困难人工标注句精调。
- 完整序列匹配率为 60.8%；达到 90%相似度的为 71.3%，达到 75%的为 82.4%。
- 输出主要是线性序列，不擅长长距离引用、分支和依赖系统状态的终止条件。

**【LLM推理】** 论文证明 LLM/模型可以恢复有限隐含动作，但不能据此假定复杂业务分支也能可靠自动补全。

### 14 Xu et al. (2021)：从事故报告扎根归纳风险因素

这篇做的是 `concept extraction`，不是关系或流程图抽取。

- 从通用词典、语料和专家知识构造施工安全领域词典。
- 85%报告机器分词，15%由三名专家核对，经过四轮迭代更新词典。
- 建立 221×2990 词项—文档矩阵，筛出 253 个高频词。
- 专家回到上下文，将词项归纳为 37 个风险因素。
- 论文承认低频词筛除可能遗漏新兴风险。

**【LLM推理】** 适合用于 P7E 扎根形成节点、关系词表和同义表达，但频率不能成为桥接候选的唯一召回标准。

### 16 ChemActor (2025)：用 LLM 合成数据补动作覆盖缺口

合成数据链为：

```text
目标分子
 -> 逆合成模型生成反应物
 -> 正向预测做自洽校验
 -> GPT-4o 生成实验描述
 -> Paragraph2Actions 生成动作
 -> GPT-4o 修整格式
```

- 不是随机接受合成数据，而是根据真实与合成数据的嵌入分布差异，补充原始数据稀疏区域。
- 增加 5 万条筛选后的合成数据后，BLEU-4 从 68.37 提升至 76.93，Exact Match 从 31.9%升至 36.4%。
- 随机加入同量数据提升较小，少量不匹配数据甚至可能降分。
- 验证包含语法、序列、参数、BERTScore、多个 LLM 评委和人工评分。
- LLM 评委整体比人工更宽松；低频动作如 `quench`、`reflux` 召回仍偏低。
- 论文正文和算法框对 KL 阈值保留方向存在表述冲突，实际实现应核对代码。

**【LLM推理】** 后续若为 P7E 建训练集，应优先寻找覆盖缺口和困难桥接，而不是随机增加容易样本。

### 26 Nan et al. (2020)：叙事临床指南到可执行规则

这不是 AI 自动抽取，而是人工知识工程流程：

```text
选择并切分指南
 -> 抽取知识
 -> 建模领域概念
 -> 编辑临床算法
 -> 用数据验证
 -> 发布
```

- 文本被拆成小逻辑块，每块明确左侧条件和右侧动作。
- 同时形成关系表和实体表，实体映射到 openEHR archetype。
- 条件—动作对转换为 GDL `when-then` 规则。
- 概念建模与规则编辑并行、双向校正；模糊内容交医学专家复核。
- 最终形成 27 个 archetype 和 18 条 GDL 规则，并人工映射到 Drools。
- 验证是把病例输入规则系统，对比输出、原指南和病例报告，而非只检查语法。
- 证据局限是只用一个公开病例，GDL 到 Drools 仍需人工，时间序列支持不足。

### 28 Lichtner et al. (2023)：适用条件与执行状态分离

这篇执行机器可读指南，不自动生成流程图。

- `Population` 表示建议适用于谁。
- `Intervention` 表示患者是否已经接受建议动作。
- 系统形成 event-condition-action 规则，分别计算“适用”与“遵循”。
- 模块包括指南接口、临床数据接口、遵循评估器和界面。
- 界面显示支撑判断的原始患者数据，供临床人员复核。
- 指南更新必须经过医院专家检查点。
- 只支持较简单的条件—动作建议，不支持复杂临床路径、不确定性和多步决策。

**【LLM推理】** P7E 不能把“下游适用”和“上游已经完成/产生状态”混成同一语义。

### 29 Hsu et al. (2025)：双 LLM 重复裁决和人工复核

这篇标题称 guideline extraction，但任务是把已整理成 JSON 的 385 条建议分为五类，不是从原始指南生成流程。

- GPT-4o 和 Gemini-1.5-Pro 对每条建议各运行 20 次。
- 先取每个模型的众数，两个模型不一致则进入人工复核。
- 另一策略合并 40 次输出，单类不足 60%即复核。
- 两模型准确率分别为 93.5%和 92.7%。
- 两模型一致的 341 条中仍有一条与专家结论不同。
- 分歧主要出现在条件分支、多基因型对应不同动作、换药或调剂量并存、证据不足等复杂情形。

**【LLM推理】** 重复推理和双模型适合定位高风险候选，但一致性不能证明真实正确，更不能替代候选召回。

## 四、建筑与法律：7 篇

### 31 Chen et al. (2024)：本体、条文分类、GPT-4 抽取和 SPARQL

流程分为四层：

```text
轻量领域本体
 -> 规范条文复杂度分类
 -> GPT-4结构化抽取
 -> SPARQL合规检查
```

- 本体通过 TF-IDF 术语抽取、语义聚类和人工调整构建。
- 条文先分为单层、双层、三层信息，再按 `Object–Property–Condition–Value` 抽取。
- GPT-4 使用每类一个示例，temperature 为 0。
- 抽取结果由确定性 Python 规则转换成 SPARQL，而不是让 LLM 直接执行。
- 融合分类模型三个类别 F1 为 0.995、0.951、0.954。
- 论文没有独立报告 GPT-4 信息抽取的 Precision/Recall，只展示案例。
- 主要覆盖量化规范，对主观、空间和跨专业规则验证不足。

### 32 Peng & Liu (2023)：规范知识图谱与 BIM 图映射

- CRF 抽实体，属性单独识别，注意力机制抽关系。
- 关系包括空间关系和数量关系，三元组进入 Neo4j。
- BIM 转成 IFCOWL/RDF；规范图和 BIM 图通过实体映射、属性映射连接。
- 检查分为直接属性、派生属性、扩展结构关系和复杂规则。
- SPARQL 负责查询，复杂计算交给外部程序。
- 输出区分 `pass / fail / warning`，warning 进入人工复核。
- 四个 BIM 项目检查准确率为 96.81%至98.17%，但主要验证规则执行，不足以证明文本自动抽取同样准确。

**【LLM推理】** P7C 节点语义和 P7E 流程语义应通过显式 mapping 连接，不能只靠名称相似。

### 34 Nawari (2019)：规范条文分类和 GAF

TRA 将条文分为：

- `Content`：定义性内容；
- `Provisory`：可执行要求；
- `Dependent`：依赖其他条文；
- `Ambiguous`：模糊要求；
- `Exception`：例外；
- `Alternative`：替代方案。

客观条文转换为对象规则和 IFC 表达；“substantial”等模糊词通过模糊集合和近似推理处理。案例把房间高度、适用对象、坡顶例外和地下室障碍转换为互相关联的形式逻辑规则，但只做小规模概念验证。

**【LLM推理】** 这些类别适合作为 P7E 扎根编码的敏感概念。定义性文本不应被强制生成流程边。

### 36 Beach et al. (2015)：RASE 语义规则和开放世界

论文区分三种语义：领域语义、具体规范语义和数据格式语义，并实际使用五类本体。

RASE 标注包括：

- `Application`：适用范围；
- `Selection`：选择范围；
- `Exception`：排除情况；
- `Requirement`：具体要求。

每项要求记录对象、属性、比较符、值、单位，并保留原始条文反向链接。规则自动转换为 SWRL，先判断是否进入适用范围，再判断通过或失败。

- 采用开放世界假设，缺少信息返回 `unknown`，不会把无法证明失败误当成通过。
- 类和属性映射支持一对一或一对多。
- 计算属性交给外部程序。
- 人工补充数据与原始数据分开保存。
- 多套法规案例与人工判断一致，但没有完整统计精度。

**【LLM推理】** `Application / Selection / Exception / Requirement` 对 P7E 很关键，模型推断节点也必须与直接证据分层。

### 37 Farghaly et al. (2022)：从事故语料扎根构建情境本体

从 165 份事故记录和 31 份新闻稿归纳八类：

- `ConstructionScope`
- `Activity`
- `BuildingElement`
- `Location`
- `RiskFactor`
- `Risk`
- `Scenario`
- `TreatmentPlan`

形成的多跳链为：

```text
工作范围
 -> 活动/构件/位置
 -> 风险因素
 -> 风险
 -> Scenario
 -> TreatmentPlan
```

`Scenario` 是容纳多个共同前提的关系节点，而不是一条普通二元边。SHE 与 IFCOWL 先自动匹配，再人工复核；即使相似度阈值为 75%，仍有大量字符串相似导致的错误映射。

**【LLM推理】** 这篇最直接支持 P7E 用扎根理论发现类型，并允许新增 flow node 表达“多条件共同构成的情境”。

### 42 Sleimi et al. (2018)：法律元数据中的条件、例外和模态

与流程相关的短语类型包括：

- `Agent`
- `Target`
- `AuxiliaryParty`
- `Action`
- `Modality`
- `Condition`
- `Exception`
- `Violation`
- `Situation`
- `Result`
- `Sanction`
- `Time`
- `Location`
- `Reason`
- `Artifact`
- `Reference`

作者先人工编码 200 条法律陈述，从中归纳句法规则和标记词，再用 150 条独立陈述评价。

- 仅评价类型时 Precision/Recall 为 97.2%/94.9%。
- 同时惩罚文本跨度错误后降为 87.4%/85.5%。
- 79.4% 的结果类型和跨度完全正确，17.8%仅部分匹配，2.8%分类错误。
- 主要错误来自多义词、并列结构、从句和介词短语错误挂接。

**【LLM推理】** P7E 不能只问关系类型是否正确，还必须检查桥接是否落到 card 内准确的 source/target node。

### 43 Chen et al. (2020)：法律实体与关系联合抽取

- 从 1750 条中文涉毒裁判事实描述中联合抽取实体和四类关系。
- RoBERTa 加入毒品词典特征；LSTM 指针解码器生成可重叠三元组；BIO 标注作为辅助任务强化实体边界。
- 最终 Precision/Recall/F1 为 86.8/80.6/83.6。
- 纯流水线 F1 仅 36.3；加入大量过滤规则后约79.6；联合模型约83.1。
- 只处理句内事实，不处理跨段落时序、条件、例外、指代和完整流程。

**【LLM推理】** 联合节点—边抽取适合 card 内部和局部关系，但跨 card 仍需要候选检索、语义裁决和全局图约束。

## 五、什么才是“多跳流程知识”

三组子代理的总结显示，论文中的多跳知识至少有四种形态。

### 1. 动作顺序链

```text
Action A -> Action B -> Action C
```

化学动作序列最典型，但它通常假设流程接近线性。

### 2. 条件—判断—动作链

```text
Condition -> Gateway/Decision -> Action -> Result
```

PET、医学指南和建筑 RASE 都说明条件不应只是边上的一段说明。

### 3. 多前提情境链

```text
Actor/Object/State/Location/Time
        -> Scenario
        -> Risk/Decision/Requirement
        -> Treatment/Action
```

此时 `Scenario` 是关系节点，用于表达多个共同成立的前提。

### 4. 跨表示映射链

```text
原始文本
 -> 抽取语义
 -> 领域本体/规则
 -> 数据对象
 -> 查询或执行结果
```

建筑和医学论文强调，文本规则与真实对象之间需要显式 mapping；抽取正确不代表映射和执行也正确。

## 六、三组总结特别提醒的证据风险

1. Friedrich 的 76.98% 是图相似度，不等于所有真实边召回率。
2. PET 和 Neuberger 显示，使用正确节点时关系模型很好，端到端却显著下降；不能只引用关系模型单项成绩。
3. Carriero 的人工感知质量不等于工业执行正确性。
4. 化学动作抽取主要是线性序列，不能直接推广到复杂分支业务流程。
5. 医学 Nan 和 Lichtner 主要是人工知识工程或规则执行，不是自动流程抽取。
6. Hsu 的任务是五分类，不是指南到流程图；双模型一致仍会共同犯错。
7. 建筑 Chen 的分类 F1 很高，但没有单独报告 GPT-4 结构化抽取的 Precision/Recall。
8. 建筑 BIM 案例的高准确率主要证明规则执行，不足以证明规范文本抽取。
9. 字符串或向量相似可产生大量错误本体映射，不能作为桥接成立证据。
10. 现有论文都没有真正验证整本书、跨章节、跨 card、节点级高召回流程重建。

## 七、对子代理结果的 P7E 综合解释

以下全部属于 **【LLM推理】**。

### 1. P7E 的核心职责

P7E 应是增量流程构图器，而不是一次性绘图器：

```text
高召回候选桥接
 -> 节点级语义裁决
 -> 必要时生成最小中间节点
 -> 图约束/场景执行验证
 -> 风险分层人工复核
```

### 2. 最值得借鉴的跨领域组合

- 用 37 的事故语料扎根方式发现 `Scenario` 等节点和关系类型；
- 用 34/36 的 `Dependent / Application / Selection / Exception / Alternative / Requirement` 组织条件语义；
- 用 PET 的 `Gateway / Condition / Same Gateway / Flow` 表达分支结构；
- 用 42 的文本跨度校验保证桥接落到具体节点；
- 用 04/05 的实体归并和分阶段抽取产生候选与语义判断；
- 用 29 的重复/双模型分歧定位需要复核的困难边；
- 用医学规则执行和建筑 SPARQL 检查验证图是否在具体情境下走到正确出口。

### 3. 每条桥接至少需要保存

- 源 card 和源 exit node；
- 目标 card 和目标 entry node；
- 关系类型；
- 适用条件、例外和替代路径；
- 触发事件、时序或必要状态；
- 原文证据和文本跨度；
- 是否为 `llm_inferred`；
- 推理摘要；
- 置信度或模型分歧；
- `pending / approved / rejected / unknown` 复核状态。

### 4. 评价指标

P7E 不能只报告 JSON/schema 通过率，应至少报告：

- 候选边召回率；
- 真实桥接召回率；
- 节点级端点准确率；
- 条件和例外保真率；
- 多跳路径召回率；
- 推断节点准确率；
- 孤立入口/出口率；
- 给定情境从入口到正确出口的可达率；
- 人工复核量及分歧样本中的错误富集率。

## 八、最终判断

三个子代理在没有统一模板的情况下都没有得出“让 LLM 直接读全书生成图”的方案。它们独立指向的是同一种工程架构：以高召回候选保护真实桥接，以节点级语义和情境节点承载多跳关系，以确定性图校验和实例执行验证约束模型，再把隐含节点、分歧和 `unknown` 交给人工复核。

因此，下一步 P7E 原型最值得验证的不是模型能画出多漂亮的图，而是：在一批人工确认的真实桥接中，候选阶段是否把它们全部找出来；找到后，模型是否能落到正确的 exit/entry node，并准确恢复中间的条件、情境和分支结构。
