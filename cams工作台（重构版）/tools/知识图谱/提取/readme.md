# CAMS 教材知识图谱提取

> V6 KG 研究 SOP：本文基于 `v6_clean.md`、`v6s_N*` 和旧工作台数据。文中的“当前可用”“正式产物”和前端同步均按 V6 历史语境理解。V7 正式 KG 位于 `../../../v7/知识图谱提取/`。

参照 `D:\ai-math\教材提取模块\高代提取` 的流水线架构，为 CAMS 反洗钱教材构建教材知识图谱（`kg_data.json`）。本目录是已完成的教材 KG 提取流水线，不是图谱化考点或题目证据绑定流水线。

## 核心原则

1. **节点由 LLM 阅读原文自主发现**，不以 H3 小节为强制模板。H3 是参考线索，不是枷锁。
2. **一次 LLM 调用只做一件事**。抽取、审核分开。
3. **每章独立运行**，最后合并。中间产物 JSONL。
4. **每条知识必须有证据**（evidence_span），可追溯到教材原文。
5. **显式边和隐式边分层处理**。显式边来自同节/同章原文证据；隐式边来自跨章节点的语义相似与 LLM 关系评估，作为增强产物单独保存。

## 当前目标：全链路质量提升

当前工作的目标不是单纯增加节点、边或句卡数量，而是更新知识图谱提取机制，提升图谱质量，使其能够用于教研展示、题目解析和后续答疑。

本轮优化要解决的问题：

- 知识点之间不能充满无关项。
- 知识点之间的关系不能与教材表述冲突。
- 每个知识点下面的证据句卡必须干净，不能混入只是语义相近但不支撑该知识点的句子。
- 隐式边可以保留，但必须符合教材表达的意思；不能只因为向量相似就进入正式图谱。
- LLM 可以参与节点、边、句卡挂载的二次裁判，但裁判依据必须包含教材原文、节点证据和上下文位置。

### 什么是“好图谱”

好图谱不是“边越多越好”或“召回越高越好”，而是能够忠实表达教材知识结构。

质量标准：

1. **教材忠实性**  
   节点、定义、关系和句卡证据都必须能回到教材原文。若图谱表达与教材语义冲突，以教材为准。

2. **节点清晰性**  
   一个节点应表达一个相对稳定的知识点、制度、机构、风险信号或案例。节点不能过泛，也不能把多个不同概念混在一起。

3. **证据闭环**  
   每个节点必须有 `evidence_span`。节点下展示的句卡应当真正支撑该节点，而不是泛相关句子。

4. **关系准确性**  
   边的方向、类型和 detail 必须符合教材意思。尤其是 `包含`、`依据`、`导致`、`前提` 等关系，不能只靠两个词相近。

5. **层级边界清楚**  
   同一小节内的显式关系优先；跨章、跨节关系必须标明是隐式增强，并通过更严格审核。

6. **可解释和可审核**  
   每个节点、边、挂载都应留下来源、方法、分数或审核理由。教研看到任何一个点，都能追问“为什么是它”。

7. **低污染优先**  
   图谱用于教研展示时，错挂和错边会破坏信任。因此正式图谱宁可少一些，也不能混入明显无关项。

### 如何表示完整教材的意思

完整教材意思不能靠单个句子或单次向量相似度表达，而应由三层共同表示：

1. **局部原文层**：每个节点和显式边必须绑定教材中的原文证据。
2. **章节语境层**：节点和句卡要保留 `chapter/section/subsection/source_line/chapter_path`，避免短句脱离原来的小节语境。
3. **全书关系层**：隐式边用于表达跨章节联系，但必须引用两端节点的已证据化定义，并标记 `source: "hidden"`、`strength`、`detail`，不得伪装成原文直接证明的显式边。

## 改进后的实验流程

新教材实验建议以当前主线为 baseline，再跑一条质量优先的改进线，产物与主线分开。

### Phase 1：基线提取

沿用当前 01-05 主线，得到一版 baseline：

- 教材树
- 节概要
- 节点
- 显式边
- 隐式边
- 句卡挂载
- `kg_data.json`

baseline 的作用是对比，不直接代表最终质量达标。

### Phase 2：全链路质量评估

对 baseline 做抽样评估：

| 对象 | 评估问题 |
|---|---|
| 节点 | 是否忠实教材？是否过泛/过细？是否有明确 evidence_span？ |
| 显式边 | 边的方向、类型、detail 是否能由原文支持？ |
| 隐式边 | 是否符合教材整体意思？是否只是词面/向量相似？ |
| 句卡挂载 | 句卡是否真支撑节点？是否只是泛相关？ |
| 组装结果 | 是否存在同名节点误合并、边丢失、隐式边来源丢失等问题？ |

建议先建立一批人工评测样本，每章抽若干节点，重点看机构、法规、目标、风险信号和案例类节点。

### Phase 3：质量优先改进线

改进线不是完全推翻主线，而是在关键质量点上加约束。

1. **节点提取改进**
   - LLM 输出节点时必须说明节点为何成立。
   - 节点定义必须压住教材原意，不能泛化到教材没有说的范围。
   - 对同名/近名节点增加“是否同一概念”的合并审核，避免误合并或重复节点。

2. **显式边改进**
   - 显式边必须有原文证据，且 detail 不能超过原文含义。
   - 审核时要求 LLM 判断：关系类型、方向、原文支撑、是否过度推断。
   - 对 `包含/依据/导致/前提` 设置更严判断标准。

3. **隐式边改进**
   - BGE 只做候选召回，不能直接决定入图。
   - LLM 审核隐式边时必须看到两端节点的 title、definition、evidence_span、章节位置。
   - 隐式边必须保持增强层身份，标记 `source: "hidden"`。
   - 若隐式边与任一端节点的原文证据冲突，必须拒绝。

4. **句卡挂载改进**
   - 原文证据优先，句卡 `citation` 命中节点 `evidence_span` 时作为强证据。
   - 教材位置优先，优先考虑同 leaf / 同 subsection / 同 section。
   - BGE 只生成 top-k 候选，不直接作为最终挂载。
   - 对 BGE 候选做严格审核，审核输入必须包含句卡 citation、context_before、context_after、chapter_path 和节点 evidence_span。
   - LLM 审核失败或无返回时，默认 `review`，不能默认 `accept`。

### Phase 4：独立产物与对比

改进线产物必须与主线分开，例如：

- `work/planb_mounts*/`
- `kg_data_planb.json`
- `quality_report_planb.md`

对比项：

- 节点保留率
- 边保留率
- 隐式边通过率
- 句卡强证据覆盖率
- 抽样准确率
- 典型错误案例

只有抽样质量达标后，才考虑替换 `data/derived/kg_data.json`。

## 知识图谱定义

## V7 节点粒度约定

V7 新教材实验中，节点粒度按以下原则控制。目标是让图谱既能表达教材结构，又不把图谱拆成大量难以审核的碎片节点。

### 机构类节点

采用中粒度。

示例：

- `金融行动特别工作组`
- `FATF 40项建议`
- `FATF互评机制`
- `FATF成员与观察员`
- `FATF不合作国家程序`

不把所有 FATF 内容都塞进 `金融行动特别工作组` 一个节点；也不默认把每条建议、每个直接目标都拆成独立节点。机构总节点与专题节点之间可用 `包含/依据/并列` 等关系连接，但关系必须符合教材表述。

### 目标/原则类节点

采用“总目标节点 + 子目标节点”的结构。

示例：

- `GIABA的目标`
- `GIABA保护成员国金融系统`
- `GIABA改善打击犯罪所得措施`
- `GIABA巩固成员国合作`

`GIABA的目标` 可以通过 `包含` 边连接到三个子目标节点。每个子目标节点必须有对应原文证据，不能只是从总目标中自由发挥出来的概括。

### 法规/指令类节点

采用法规总节点为主，细项优先作为句卡证据挂载。

示例：

- `第5号反洗钱指令`

其下挂载教材中关于义务主体范围、受益所有人、预付卡匿名门槛、高风险第三国等内容的证据句卡。除非某个细项在教材中跨段落反复出现、参与多个关系或具有独立考点意义，否则不默认拆成单独知识节点。

### 风险信号类节点

采用风险信号总节点为主，下面挂载按类型组织的证据。

示例：

- `贸易洗钱危险信号`

其下可以按证据分组呈现：

- 贸易文件异常
- 交易价格异常
- 付款路径异常
- 客户行为异常
- 货物流与资金流不匹配

这些分组优先作为节点下的证据组织方式，而不是默认进入图谱成为独立节点。只有当教材把某类风险信号作为独立小节或独立考点反复展开时，才考虑拆成节点。

### 粒度总原则

1. 机构、制度、机制、方法适合中粒度节点。
2. 目标/原则如果教材明确列项，可拆成“总节点 + 子节点”。
3. 法规/指令优先保持总节点，细项先作为证据句卡。
4. 风险信号优先保持总节点，细项先作为证据分组。
5. 是否拆节点，取决于该内容是否在教材中具备独立语义、独立证据和独立关系价值。

### 节点类型（类比数学 KG 的 Concept/Method/Theorem）

| 类型 | 含义 | 例子 |
|---|---|---|
| KnowledgePoint | 一般知识点 | "洗钱的定义""FATF 40项建议""风险为本方法" |
| Regulation | 法规/标准 | "欧盟第4号反洗钱指令""美国爱国者法案" |
| RiskIndicator | 风险指标/危险信号 | "异常现金交易""拆分交易" |
| CaseStudy | 案例节点 | "代理银行业务（案例）" |
| Institution | 机构/组织 | "金融行动特别工作组""巴塞尔委员会" |

### 关系类型（6 种，对标数学 KG 的 7 种核心关系）

| 类型 | 含义 | 示例 |
|---|---|---|
| 包含 | A 是 B 的上位概念 | FATF 包含 FATF 40项建议 |
| 并列 | A 和 B 同属一个系列 | 第3号指令 并列 第4号指令 |
| 导致 | A 引发 B | 洗钱 导致 税收损失 |
| 缓解 | A 降低风险 B | 增强尽调 缓解 代理行风险 |
| 前提 | A 是 B 的前置条件 | 身份识别 前提 风险评估 |
| 依据 | A 的法律来源是 B | KYC制度 依据 FATF建议 |

## 流水线步骤（对应高代提取）

### Step 0：教材树（机械，不调 LLM）

`01_build_textbook_tree.py`

从 `v6_clean.md` 提取 H2/H3 结构，生成 `leaf_sections.jsonl`（每个 H3 一节 + 段落原文）。

对应：高代 Step 1 `01_build_textbook_tree.py`

### Step 1：节概要（LLM）

`02_section_summaries.py`

为每个 H3 节生成轻量导航信息：`summary`（一节讲什么）+ `skip_reason`（无实质内容时的跳过原因）。不再生成 `key_terms`；不做节点发现，不做关系抽取。

对应：高代 Step 2 `02_generate_section_summaries.py`

### Step 2：显式节点提取（LLM）

`03_extract_nodes.py`

LLM 阅读每个 H2 节的原文，自主发现其中的知识点节点。每个节点需附带：
- `title`、`definition`、`node_type`、`evidence_span`
- 不限于 H3 标题——LLM 可以合并、拆分、新增

对应：高代 Step 3 `03_extract_explicit_nodes.py`

### Step 2A：节点审核（LLM）

`03a_audit_nodes.py`

对 Step 2 的节点候选做全量审核：`accept` 入图 / `review` 入待审队列。硬规则校验：标题非空、evidence 在原文中、类型合法、无重复。

对应：高代 Step 3A `03a_audit_explicit_nodes.py`

### Step 3：关系边提取（LLM）

`04_extract_edges.py`

在定稿节点集上，LLM 阅读原文，发现节点间的 6 种关系。输出有向边。

对应：高代 Step 4A `04_extract_explicit_edges.py`

### Step 3A：边审核（LLM）

`04a_audit_edges.py`

审核边：方向是否正确、关系类型是否合理、detail 是否引用原文。

对应：高代 Step 4C `04c_audit_edges_and_rule_cases.py`

### Step 3B：待审项终审（LLM）

`04b_ai_review.py`

收集各章 `nodes_review.jsonl` 和 `edges_review.jsonl`，让 LLM 对初审进入 `review` 的节点/边做最终裁决。通过的节点追加到 `nodes_accepted.jsonl`；通过的边追加到 `edges_accepted.jsonl` 和 `edges_for_merge.jsonl`。

对应：高代 Step 7A/7B/7D 的精简合并版。

### Step 3C：隐式边发现（BGE + LLM，跨章增强）

`04c_hidden_edges.py`

在全书已通过审核的节点上发现跨章语义关系：

1. 用 `definition + title` 计算 BGE 向量，按余弦相似度预筛候选节点对。
2. 跳过已经存在显式边的节点对，跳过同 H2 节节点对，避免重复覆盖 Step 3。
3. 对候选节点对进行 LLM 评估，判断是否存在 6 种关系之一，并给出 `type`、`strength`、`detail`。
4. 仅保留强度达标的关系，输出 `work/edges_hidden.jsonl`。

隐式边字段中会标记 `source: "hidden"`。它没有教材原文中的连续 `evidence_span`，因为依据是两个已证据化节点之间的跨章语义联系；因此它应被视为图谱增强产物，而不是同显式边完全等价的原文证据边。

对标：TreeKG HiddenKG/Pred.py。

### Step 4：句卡挂载候选生成（机械 + BGE 兜底）

`05_mount_cards.py`

将 `cards_v6_sentence.json` 中的句卡挂到已通过审核的节点上：

- 路 A：citation/knowledge 与节点证据文本做确定性匹配。
- 路 B：未匹配句卡使用 BGE 向量兜底。

输出各章 `card_mounts.jsonl`。这一步只生成候选，不直接进入最终图谱。

注意：旧版 Step 4 对短句、列表项和泛语义句卡不够稳健。BGE top1 可能把缺少实体锚点的短句挂到语义相近但教材语境不同的节点。当前质量改进以 `05_mount_cards_v2.py` / `planb.md` 为实验线，强调 evidence_span 和教材位置优先。

### Step 4A：句卡挂载审核（LLM + 自动放行）

`05a_audit_mount.py`

对挂载候选做审核：

- citation 匹配或 BGE 分数高于阈值的候选自动 `accept`。
- 低置信度 BGE 候选交给 LLM 判断 `accept/review`。

输出各章 `card_mounts_audited.jsonl`。最终组装只使用审核后 `accept` 的挂载。

注意：旧版 Step 4A 中 `BGE >= 0.7` 自动放行的策略可能放大泛相关误挂。新实验线中，BGE 只应作为候选召回，最终挂载需要证据命中、教材位置或严格审核支撑。

### Step 4B：Plan B 句卡挂载实验线（质量优先）

`05_mount_cards_v2.py`

该脚本用于验证改进后的句卡挂载策略，默认产物与主线分开，不覆盖 `work/ch*/card_mounts*.jsonl`。

核心策略：

- `citation/knowledge` 命中节点 `evidence_span` 的，作为强证据候选。
- 使用 `source_line_start/chapter_path` 与节点 `section/subsection/section_node_id` 判断教材位置对齐。
- BGE 只生成 top-k 候选，不直接作为最终 accept。
- 每个候选保留 `method/score/source_alignment/reason`，便于追溯。

详见 `planb.md`。

### Step 5：最终组装（机械）

`05_assemble.py`

收集各章通过审核的节点、关系边和审核后的句卡挂载，做跨章去重，输出 `data/derived/kg_data.json`。

当前完成版 `kg_data.json` 已包含 228 条隐式边。复现或重跑组装时，需要确认隐式边是否按当前策略合入，避免只收集 `edges_accepted.jsonl` 后把隐式边洗掉。

输出结构：

- `card_id -> {section, edges}`：句卡所属知识节点和相关边。
- `_edges`：概念之间的显式/隐式关系边。
- `_stats`：节点、边、挂载句卡等统计。

对应：高代 Step 5A `05_global_normalize_and_review.py` + Step 8A `08a_assemble_final_graph.py`
