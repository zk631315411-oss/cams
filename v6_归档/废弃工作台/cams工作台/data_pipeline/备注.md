## bind_qa.py 详细说明

### 输入输出

- 输入：
  - `data/qa.json`（答疑记录）
  - `data/questions.json`（题目）
  - `data/question_card_map.json`（题目→句卡映射，用于句卡继承）
- 输出：`data/qa_bindings.json`

### 绑定方法（三段式 + LLM 审核）

1. **关键词匹配**：对每条答疑按 `source_file` 文件名正则 `(\d+)\.(\d+)` 提取 section，在同 section 题目里做词集交集打分。
2. **BGE 兜底**：score < 3 的低质量绑定用 `BAAI/bge-small-zh-v1.5`（sentence-transformers，`local_files_only=True`）在全题库做向量召回。
3. **DeepSeek flash 审核**：用 `deepseek-chat`（temperature=0）逐条判断"答疑和题目是否同一道题"，写 `flash_approved`。
4. **继承句卡**：从 `question_card_map.json` 取题目已绑定的句卡 ID 写入 `inherited_card_ids`。

### 输出字段

```json
{
  "qa_id": "QA_...",
  "source_file": "...",
  "qa_question": "...",
  "bound_question_id": "2.8_13",
  "bound_question_stem": "...",
  "match_method": "keyword | bge",
  "match_score": 0.85,
  "flash_approved": true,
  "inherited_card_ids": ["v6_b08_N17"]
}
```

### 章节相关性

**章节无关**——脚本可以从文件名正则提取 section 分桶匹配，BGE 兜底是全题库检索，句卡继承从 `question_card_map.json` 取，不写死第二章。**所以扩展到 3/4/5/6 章不需要改脚本本身**，但需要满足前置条件。

### 扩展到 3/4/5/6 章的前置条件

1. `qa.json` 已含 3-6 章答疑记录（`parse_qa.py` 产出）。
2. `questions.json` 已含 3-6 章题目（`parse_questions.py` 产出）。
3. `question_card_map.json` 已覆盖 3-6 章题目↔句卡映射（`match_questions.py` 产出，**当前未重跑，扩展答疑前必须先扩展它**，否则 `inherited_card_ids` 会全空）。

### 扩展时建议的小改造（非重写）

1. **产物路径对齐**：脚本当前写 `data/qa_bindings.json`，但前端 `workbench-store.js` 优先读 `data/teaching_assets/qa_bindings.json`。重跑后需把产物放到 `teaching_assets/`，或改 `OUT` 常量。
2. **第 6 章编号**：第 6 章题目采用主题式编号（`6.KYC`、`6.人口贩卖` 等），不是 `6.1`/`6.2` 形式。`(\d+)\.(\d+)` 正则可能解析失败走 `unknown` → fallback 全题库匹配，仍能跑但精度下降。建议为第 6 章补 section 提取规则。
3. **密钥硬编码**：`DS_KEY` 写在源码里（行 10），能跑但不安全，建议改读环境变量。
4. **BGE 模型**：需本机已下载 `BAAI/bge-small-zh-v1.5`（`local_files_only=True`）。

## bind_qa.py 与学生答疑模块（agentic）的关系

**两条独立线，互不依赖**：

| 维度 | bind_qa.py | agentic 答疑模块（`cams工作台/学生答疑模块_agentic/`，:8766） |
|---|---|---|
| 类型 | 离线一次性脚本 | 在线 HTTP 服务 |
| 输入 | `qa.json` + `questions.json` + `question_card_map.json` | 老师粘贴的学生提问文本 |
| 产出 | `qa_bindings.json`（答疑↔题目↔句卡 绑定） | `outputs/drafts/qa_agentic_*.json`（答疑草稿） |
| 是否入正式库 | 是（前端 store 加载展示） | 否（草稿暂存，不写入 `qa.json` / `qa_bindings.json`） |
| 用途 | 工作台展示"历史答疑与题目/句卡的绑定关系" | 实时生成新答疑草稿 |
| 匹配方法 | 关键词 + BGE + LLM 审核 | 题干相似度（ratio + jaccard + option） |
| 是否被对方引用 | agentic 不读 `qa_bindings.json` | bind_qa.py 不调 agentic |

**前端同时用两样东西**，用途不同：
- `qa_bindings.json` → 工作台展示历史答疑与题目/句卡的绑定关系（静态加载，见 `workbench-store.js:257`）
- :8766 agentic API → 老师粘贴新学生提问，实时生成答疑草稿（见 `workbench-app.js:764`）
