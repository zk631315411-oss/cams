# Plan B：知识库版本演化管理方案

## 问题本质

v6 → v7 不是一次性任务，而是**知识库的版本演化管理**问题：

> 当底层教材发生结构性变化时，上层的题库和知识体系如何高效更新？

教材章节可重构、术语可替换，但知识点的实质是相对稳定的。解决这个问题的关键是：**用一套独立于教材版本的知识点体系作为中间层**。

```
v6教材 ←→ 知识点体系 ←→ v6题库
                ↕
v7教材 ←→ 知识点体系 ←→ v7题库（更新中的题库）
                ↕
v8教材 ←→ 知识点体系 ←→ v8题库
```

版本变了，只需更新"知识点 ↔ 教材位置"的映射，题和知识点的关联不用动。

## 两层对比方案

### 第一层：Topic 级变化概述（以 v6 目录为骨架）

- 以 v6 Ch2 的 73 个 `###` 为 Topic 单元
- 双路检索（bge 语义 + 关键词）在 v7 中找 Top-5 候选段落
- LLM 并排阅读 v6 原文 + v7 候选段落，输出结构化变化概述
- 自动分类：
  - 完全对应（bge ≥0.7 且 LLM 确认）→ 自动通过
  - 部分对应/无对应 → 标记为"需人工审核"，附带 v6 原文 + v7 候选段落

### 第二层：知识点体系构建（暂缓，第一层验证后考虑）

- 从 v6 和 v7 中抽取知识点，构建版本无关的知识点 ID 体系
- 知识点 ↔ 教材位置建立可更新的映射表
- 未来 v8 发布时，仅需更新映射，题库侧不动

## 与当前主计划的区别

| | 主计划（Plan A） | Plan B |
