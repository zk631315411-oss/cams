# 选项级解析与教材依据绑定改造计划

## 0. 任务结论

当前流水线不能直接满足“把题目以及选项与对应的教材原文进行联系”的需求。它只能生成题目级 `ai3_output` 文本和题目级 `cited_cards` 汇总，缺少稳定的选项级结构化绑定。

本次改造目标是：在保留“四角色法”基本思路的前提下，根据“题目 + 选项 + 标准答案”生成可供教研审核使用的选项级解析，并同时找出哪些教材句卡可以作为每个选项判断的依据。

最终产物不是单纯的“证据绑定表”，也不是单纯的“AI 讲题文本”，而是：

```text
题目 -> 选项 -> 可用解析 + 教材句卡证据 + 证据状态 + 教研复核标记
```

## 0.1 模块定位：解析层与证据层解耦

本模块同时服务两件事，但必须分层处理：

1. **解析层**：根据题目、选项和标准答案，生成每个选项为什么对/错、学生容易怎么误解的解析初稿。
2. **证据层**：为每个选项判断寻找可作为依据的教材句卡，并判断证据强弱。

两层不能混在一起：

1. 解析可以成立，但证据可能只是 `indirect` 或 `none`。
2. 没有 `direct` 教材句卡，不等于解析失败。
3. 没有 `direct` 教材句卡时，必须保留解析，同时把 `evidence_status` 标为 `indirect` / `none` / `needs_manual`，并在正确选项上标 `needs_teacher_review=true`。
4. 只有“解析结构缺失、选项数量不一致、JSON 无法解析、判断与标准答案冲突”等问题，才算结构或解析失败。

一句话：**本模块要生成可用解析，并诚实标注这些解析有没有教材原文证据。**

## 0.2 当前阶段成功标准

第一阶段不要求所有选项都找到 `direct` 证据。第一阶段成功标准是：

1. 每道题的所有选项都有结构化解析。
2. 每个选项都有 `judgement`、`explanation`、`common_trap`、`evidence_status`。
3. 所有引用的 `card_id` 都真实存在，且来自本次提供给证据裁判的候选证据。
4. 正确选项没有 `direct` 证据时，不得标 `answered`，必须标 `partial` 并要求教研复核。
5. direct 覆盖率要单独统计，低覆盖率说明召回/证据定位还需要优化，不说明解析层失败。

## 0.3 检索策略结论：不能只做直接 BGE

已试跑确认：直接 BGE 或“AI #2 query -> BGE 章节节点 -> 取前几张卡”的质量一般，原因不是 BGE 完全无用，而是它只解决“语义相似”，不能稳定解决考试题里的“判断依据”问题。

典型问题：

1. 题目和教材表述不一致，例如题目说“业务目的不符”，教材可能写“没有明显业务理由或者与客户业务/历史交易不符”。
2. 错误选项需要找“反驳证据”或“排除条件”，不是找同义句。
3. 多选题每个选项对应的证据需求不同，不能用全题 query 混在一起搜。
4. BGE 容易抓到同一大主题下的泛化句，导致 `indirect` 多、`direct` 少。
5. 章节级 BGE 再取章节前几张卡，容易错过同章节中真正关键的后续句卡。

结论：**直接 BGE 只能作为 baseline 和召回子工具，不能作为正式证据绑定方案。**

## 0.4 正式方向：选项级 Agentic Search

正式方案采用“选项级 agentic search”，不是简单多写几个 query。

核心流程：

1. **搜索规划员**：根据题目、选项、标准答案，把每个选项改写为 `option_claim`、`evidence_need`、`search_queries`、`must_terms`、`related_terms`、`contrast_terms`。
2. **多路召回**：对每个选项单独召回候选教材句卡，至少包括 card-level BGE、稀疏关键词检索、精确短语命中、相邻句卡补充、低权重 `card_relations.json` 扩展。
3. **证据裁判**：只看题目、标准答案、该选项候选句卡，输出结构化 `option_analysis`；不允许引用候选集外的 `card_id`。
4. **补搜回合**：如果正确选项没有 direct 证据，证据裁判必须输出 `followup_queries_by_option`，再检索一轮。
5. **结构护栏**：程序层面强制校验并清洗输出：`none` 不允许保留 `evidence_cards`；`negative` 只能作为 `support_type`，不能作为 `evidence_status`；`direct` 必须有真实候选卡。
6. **LLM 教材句卡扫描**：当常规多路召回仍找不到正确选项 direct 证据时，可以把 `cards_ch2.json` 句卡目录按块提供给 LLM 扫描。扫描器只能从当前块内真实 `card_id` 中挑候选，不写最终解析。扫描结果仍必须进入证据裁判，不能直接落入最终 `evidence_cards`。

## 1. 服务对象与最终用途

服务对象：教研。

教研需要看到：

1. 每道题的题干、完整选项、标准答案。
2. 每个选项的判断：正确、错误、证据不足、待人工确认。

6. 哪些解析已有直接教材证据，哪些只是间接支撑，哪些必须教研人工处理。

不服务学生端展示，不做美化型前端，不做考试刷题功能。

### 6.2 `option_analysis` 必须结构化

每个选项一个对象：

```json
{
  "option": "A",
  "option_text": "在整个欧盟建立一致的监管环境，以防止洗钱",
  "is_correct_answer": true,
  "judgement": "correct",
  "judgement_confidence": "high",
  "evidence_status": "direct",
  "evidence_cards": [
    {
      "card_id": "v6_b01_N01",
      "support_type": "direct",
      "source": "bge_direct",
      "quote": "教材原文短摘录，不超过120字",
      "reason": "这句话为什么能支撑该选项",
      "relevance": "high"
    }
  ],
  "kg_concepts": [
    {
      "name": "欧盟反洗钱指令",
      "role": "辅助概念，不是教材依据"
    }
  ],
  "explanation": "为什么该选项正确或错误",
  "common_trap": "学生容易误选/误排除的原因",
  "needs_teacher_review": false,
  "teacher_review_reason": ""
}
```

字段来源说明：

1. `evidence_cards`：只能来自本题传给 AI #3 的教材句卡证据，且 `card_id` 必须真实存在于 `cards_ch2.json`。
2. `explanation`：必须优先基于 `evidence_cards` 和题目标准答案推理；没有直接证据时要明确写证据不足，不能伪装成教材结论。
3. `common_trap`：这是教学推断字段，不是教材依据字段。AI 可以基于题干、选项差异、标准答案、教材证据和一般考试干扰项逻辑生成，但必须满足：
   - 不得写成“教材说学生会这样错”。
   - 不得引用不存在的学生数据。
   - 若只是推断，措辞用“可能误以为”“容易混淆为”“常见干扰在于”。
   - 若无法合理推断，填空字符串 `""` 或 `"待教研补充"`。
4. `kg_concepts`：第一阶段不是必填字段。可以先统一输出空数组 `[]`。只有在明确做了选项到 `kg_data.json` 概念节点的匹配后，才填入具体概念；不能让 AI 凭空编概念节点。

### 6.3 枚举值

`judgement` 只能使用：

1. `correct`
2. `incorrect`
3. `insufficient`
4. `needs_manual`

`evidence_status` 只能使用：

1. `direct`：至少一条教材句卡直接支撑该选项判断。
2. `indirect`：有相关教材句卡，但只能类比或背景支撑，不能算直接教材依据。
3. `none`：未找到可用教材句卡。
4. `conflict`：候选证据与标准答案或选项判断冲突。
5. `needs_manual`：模型无法判断，需要教研人工处理。

`support_type` 只能使用：

1. `direct`
2. `indirect`
3. `context`
4. `negative`

`relevance` 只能使用：

1. `high`
2. `medium`
3. `low`

### 6.4 全题 `status` 判定规则

全题 `status` 只能使用：

1. `answered`
2. `partial`
3. `evidence_insufficient`
4. `ai1_failed`
5. `ai2_failed`
6. `ai3_failed`
7. `parse_failed`
8. `needs_manual`

判定规则：

1. 所有选项都有明确 `judgement`，且标准答案中的每一个正确选项都有至少一条 `direct` 证据，全题才可以为 `answered`。
2. 部分选项有明确判断或部分选项缺直接证据，全题为 `partial`。
3. 全部选项都没有可用教材证据，全题为 `evidence_insufficient`。
4. AI 输出无法解析为 JSON，全题为 `parse_failed`。
5. 模型明确无法判断或题目缺字段，全题为 `needs_manual`。
